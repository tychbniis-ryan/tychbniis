# 流感及新冠疫苗設站填報與民眾查詢網站開發文件

## 1. 專案目的

本專案旨在將現行以 Google Sheet 提供各區衛生所填報之「流感及新冠疫苗設站情形」資料，建置為較易於填報、管理及民眾查詢之網站系統。

系統採用 Google Sheet 作為資料儲存來源，Google Apps Script（GAS）作為填報後台與資料轉換工具，並以 Firebase Hosting 建置民眾端查詢網站。

## 3. 系統架構

```text
各區衛生所人員
  ↓
GAS 填報後台
  ↓
Google Sheet 主資料表
  ↓
GAS 資料整理與 JSON 產生
  ↓
public.json
  ↓
Firebase Hosting 民眾查詢網站
  ↓
民眾查詢設站資訊
```

## 4. 系統分工

| 模組 | 技術 | 用途 |
|---|---|---|
| 填報端 | Google Apps Script Web App | 提供各區衛生所新增、修改、下架設站資料 |
| 資料庫 | Google Sheet | 儲存設站資料、公開設定、異動紀錄、JSON 輸出紀錄 |
| 資料轉換 | Google Apps Script | 將 Google Sheet 中已公開資料整理成 JSON |
| 民眾端 | Firebase Hosting | 提供民眾查詢設站資訊 |
| 公開資料 | JSON | 作為 Firebase 前台查詢資料來源 |

## 5. 權限原則

### 5.1 目前階段

目前不設定帳號權限，知道 GAS 填報網址者均可進入填報。

### 5.2 注意事項

由於目前採用「知道連結者均可填報」，請至少保留下列管理機制：

1. 每筆資料需有資料ID。
2. 每筆資料需有最後更新時間。
3. 每次新增、修改、下架需寫入異動紀錄。
4. 民眾端僅顯示「是否公開=是」且「資料狀態=已發布」之資料。
5. 不直接將 Google Sheet 原始資料公開給民眾端。

## 9. GAS 填報後台需求

### 9.1 基本功能

GAS Web App 需提供下列功能：

1. 新增設站資料。
2. 查詢既有設站資料。
3. 修改設站資料。
4. 下架資料。
5. 顯示目前資料狀態。
6. 顯示最後更新時間。
7. 寫入異動紀錄。
8. 產生或更新公開 JSON。

### 9.2 填報欄位

填報畫面需包含下列欄位：

| 欄位 | 輸入方式 | 是否必填 |
|---|---|---|
| 行政區 | 下拉選單 | 是 |
| 里別 | 文字輸入或下拉選單 | 是 |
| 接種日期 | 日期輸入 | 是 |
| 設站時間 | 文字輸入，格式 HHmm-HHmm | 是 |
| 設站地點名稱 | 文字輸入 | 是 |
| 地址 | 文字輸入 | 是 |
| 承接醫療院所名稱 | 文字輸入 | 是 |
| 醫療院所十碼代碼 | 文字輸入 | 否 |
| 服務對象 | 文字輸入或下拉選單 | 是 |
| 流感疫苗廠牌 | 文字輸入或下拉選單 | 否 |
| 新冠疫苗廠牌 | 文字輸入或下拉選單 | 否 |
| 流感疫苗預估人數 | 數字輸入 | 否 |
| 流感疫苗接種人數 | 數字輸入 | 否 |
| 新冠疫苗預估人數 | 數字輸入 | 否 |
| 新冠疫苗接種人數 | 數字輸入 | 否 |
| 備註 | 文字輸入 | 否 |
| 是否公開 | 下拉選單：是／否 | 是 |
| 資料狀態 | 下拉選單：草稿／已發布／下架 | 是 |

### 9.3 資料檢核規則

送出資料前需檢核：

1. 必填欄位不得空白。
2. 設站時間格式需為 `HHmm-HHmm`，例如 `0800-1200`。
3. 預估人數、接種人數需為數字。
4. 接種人數不得大於明顯不合理數值；可先不強制限制，但需避免非數字。
5. 若「是否公開=是」，建議資料狀態需為「已發布」才會出現在民眾端。
6. 接種率由系統自動計算，不建議人工輸入。

### 9.4 接種率計算

```text
流感疫苗接種率 = 流感疫苗接種人數 ÷ 流感疫苗預估人數 × 100%
新冠疫苗接種率 = 新冠疫苗接種人數 ÷ 新冠疫苗預估人數 × 100%
```

若預估人數為空白或 0，接種率應顯示空白。

### 9.5 資料ID規則

建議格式：

```text
TY-YYYYMMDD-流水號
```

例如：

```text
TY-20251001-0001
```

若日期使用民國年，仍建議系統內部轉換為西元日期後產生 ID。

| 欄位名稱 | 說明 |
|---|---|
| 紀錄時間 | 系統時間 |
| 動作 | 新增／修改／下架／發布 |

| 行政區 | 對應行政區 |
| 設站地點名稱 | 對應地點 |
| 修改前內容 | 可用 JSON 字串記錄 |
| 修改後內容 | 可用 JSON 字串記錄 |
| 操作者 | 若可取得 Email 則紀錄 Email，否則紀錄空白或使用者輸入名稱 |

## 11. 公開設定表需求

「公開設定」工作表建議包含：

| 設定項目 | 內容 |
|---|---|
| notice | 接種資訊依里辦公處或轄區衛生所公告為主，接種前請務必攜帶健保卡及相關證明文件。 |
| isOpen | 是 |
| updatedAt | 系統自動更新 |
| title | 桃園市流感及新冠疫苗接種站查詢 |

## 12. JSON 產生需求

### 12.1 產生時機

JSON 產生方式建議包含：

1. 每次資料新增、修改、下架後，可手動或自動重新產生 JSON。
2. 另設定 GAS 定時觸發器，每 5 至 10 分鐘產生一次 JSON。

### 12.2 JSON 篩選條件

僅輸出符合以下條件的資料：

```text
是否公開 = 是
資料狀態 = 已發布
```

### 12.3 JSON 不應包含的欄位

民眾端 JSON 不應包含：

1. 醫療院所十碼代碼。
2. 流感疫苗預估人數。
3. 流感疫苗接種人數。
4. 流感疫苗接種率。
5. 新冠疫苗預估人數。
6. 新冠疫苗接種人數。
7. 新冠疫苗接種率。
8. 填報單位。
9. 填報人Email。
10. 內部異動紀錄。

### 12.4 JSON 格式範例

```json
{
  "title": "桃園市流感及新冠疫苗接種站查詢",
  "updatedAt": "2026-07-02 17:00",
  "notice": "接種資訊依里辦公處或轄區衛生所公告為主，接種前請務必攜帶健保卡及相關證明文件。",
  "data": [
    {
      "id": "TY-20251001-0001",
      "district": "桃園區",

      "date": "2025-10-01",
      "rocDate": "114/10/1",
      "time": "08:00-12:00",
      "rawTime": "0800-1200",
      "siteName": "南門市民活動中心",
      "address": "桃園區三民路三段268號",
      "hospitalName": "敏盛智慧健康管理診所",
      "target": "65歲以上長者",

      "covidBrand": "LP.8.1",
      "note": "南華南門西湖西門合辦"
    }
  ]

```

### 13.2 Firebase 專案

- 專案名稱：tychb-vaccineweb

1. 顯示網站標題。
2. 顯示公告提醒文字。

4. 行政區篩選。

## 17. 測試項目

### 17.1 GAS 後台測試

1. 是否可新增資料。
2. 是否可修改資料。
3. 是否可下架資料。
4. 必填欄位是否有效阻擋。
5. 時間格式錯誤是否有效阻擋。
6. 人數欄位非數字是否有效阻擋。
7. 接種率是否正確計算。
8. 是否正確寫入異動紀錄。
9. 是否正確更新最後更新時間。

### 17.2 JSON 測試

1. 是否只輸出已發布且公開資料。
2. 是否排除內部欄位。
3. 日期格式是否正確。
4. 時間格式是否轉換為 `08:00-12:00`。
5. JSON 是否可被 Firebase 前端成功讀取。

### 17.3 Firebase 前台測試

1. 手機版是否正常顯示。
2. 行政區篩選是否正確。
3. 里別篩選是否正確。
4. 日期篩選是否正確。
5. 關鍵字搜尋是否正確。
6. 無資料時是否顯示友善訊息。
7. 最後更新時間是否正確顯示。
8. 已下架資料是否不顯示。

## 18. 重要開發原則

1. 民眾端不得直接讀取 Google Sheet 原始資料。
2. 民眾端只讀取 GAS 產生之公開 JSON。
3. 內部欄位不得輸出到 JSON。
4. 設站資料應以單一主資料表管理。
5. 接種率應由系統自動計算。
6. 每筆資料應有唯一資料ID。
7. 每次修改應保留異動紀錄。
8. 手機版優先設計。
9. 未來如需正式上線，建議綁定機關正式子網域。
