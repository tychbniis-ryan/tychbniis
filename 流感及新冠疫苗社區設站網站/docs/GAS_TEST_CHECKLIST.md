# GAS 實機測試清單

本文件用於 Google Apps Script 與 Google Sheet 實機測試。測試時請使用測試用試算表與假資料，不要使用正式個資、帳密、Token、Cookie 或憑證。

## 1. 測試前準備

### 1.1 本機檢查

在貼到 Apps Script 前，先於本機執行：

```powershell
node scripts/local-check.mjs
```

預期結果：

1. GAS 程式語法檢查通過。
2. GAS HTML 內嵌 script 語法檢查通過。
3. `public/public.json` 格式檢查通過。
4. 管理碼驗證、里別未設站與統計邏輯假資料測試通過。
5. `queueUrl` 叫號連結只接受 `http://` 或 `https://` 完整網址，空白或無效網址不顯示按鈕。

### 1.2 GAS 測試環境

1. 建立一份新的 Google Sheet 測試試算表。
2. 建立或開啟綁定該試算表的 Google Apps Script 專案。
3. 將 `gas/Code.gs` 內容貼到 Apps Script 的 `Code.gs`。
4. 將 `gas/Index.html` 內容貼到 Apps Script 的 `Index.html`。
5. 第一次執行 `setupWorkbook()`，並依 Google 提示授權。
6. 確認工作表已建立：
   - `設站資料`
   - `宣導品品項表`
   - `宣導品配送任務表`
   - `廠商資料表`
   - `里別清冊`
   - `系統設定`
   - `異動紀錄`
7. 在 `系統設定` 表設定測試用管理碼。
8. 在 `廠商資料表` 建立測試廠商與測試查詢碼。

## 2. 測試資料原則

測試只能使用假資料，例如：

```text
行政區：測試區
里別：測試里
設站地點名稱：測試活動中心
地址：桃園市測試區測試路 1 號
承接醫療院所名稱：測試診所
醫療院所十碼代碼：0000000000
填報人：測試人員
廠商名稱：測試印刷公司
廠商查詢碼：TEST1234
```

不得使用：

1. 真實民眾姓名。
2. 真實身分證字號。
3. 真實電話。
4. 真實 LINE ID。
5. 正式管理碼。
6. 任何帳密、Token、Cookie 或憑證。

## 3. GAS 後台基本測試

### 3.1 初始化工作表

測試步驟：

1. 在 Apps Script 執行 `setupWorkbook()`。
2. 回到 Google Sheet 檢查工作表與表頭。

預期結果：

1. 必要工作表都存在。
2. 表頭未缺漏。
3. `宣導品品項表` 有測試用初始品項。
4. `系統設定` 有管理功能設定列。

### 3.2 新增草稿設站資料

測試步驟：

1. 部署或預覽 GAS Web App。
2. 進入「新增設站資料」。
3. 使用假資料填完 6 步驟。
4. 選擇「送出草稿」。

預期結果：

1. `設站資料` 新增 1 筆資料。
2. `資料狀態` 為 `草稿`。
3. `是否公開` 為 `否`。
4. 不應產生宣導品配送任務。

### 3.3 發布設站資料

測試步驟：

1. 進入「維護既有資料」。
2. 找到草稿資料。
3. 點選「發布」。

預期結果：

1. `資料狀態` 為 `已發布`。
2. `是否公開` 為 `是`。
3. `是否鎖定` 為 `是`。
4. 若有申請宣導品，應產生配送任務。
5. `異動紀錄` 有發布紀錄。

### 3.4 申請解鎖與審核

測試步驟：

1. 在「維護既有資料」點選已鎖定資料的「申請解鎖」。
2. 確認表單顯示資料 ID 與場次摘要。
3. 填寫假申請人並送出。
4. 到「稽催／統計」輸入測試管理碼與審核人。
5. 對待審核資料執行「核准解鎖」。

預期結果：

1. 申請後 `解鎖申請狀態` 為 `待審核`。
2. 核准後 `解鎖申請狀態` 為 `已核准`。
3. 核准後 `是否鎖定` 為 `否`。
4. `異動紀錄` 有申請與審核紀錄。

補充測試：

1. 將同一筆接種站的宣導品配送任務狀態改為 `已配送`。
2. 回到「維護既有資料」嘗試申請解鎖。
3. 確認系統阻擋申請，並顯示無法解鎖修改的訊息。
4. 若已有待審核申請，再到「稽催／統計」嘗試核准解鎖。
5. 確認系統阻擋核准。

### 3.5 管理作業入口驗證

測試步驟：

1. 確認 `系統設定` 表的 `管理功能密碼` 已填入測試管理碼。
2. 回到 GAS 後台首頁。
3. 點選「稽催／統計」。
4. 先輸入錯誤管理碼。
5. 再輸入正確測試管理碼。
6. 驗證通過後，再點選「宣導品管理」與「系統工具」。
7. 點選「廠商配送回報」。

預期結果：

1. 錯誤管理碼會被阻擋。
2. 正確管理碼可進入稽催／統計。
3. 同一頁面工作階段通過驗證後，可進入宣導品管理與系統工具。
4. 廠商配送回報不要求管理碼，仍使用廠商名稱與廠商查詢碼。
5. 管理碼不得顯示在畫面或寫入程式碼。

### 3.6 編輯已解鎖資料

測試步驟：

1. 在「維護既有資料」找到已解鎖資料。
2. 點選「編輯資料」。
3. 修改地址或備註。
4. 點選「儲存修改」。

預期結果：

1. 原資料列被更新。
2. 不會新增第二筆重複資料。
3. `異動紀錄` 有修改紀錄。
4. 若有未配送、配送中或異常的宣導品配送任務，配送地址、聯絡人、電話、備註、品項與數量會同步更新。
5. 若取消某個宣導品品項，對應未完成配送任務狀態會改為 `取消`。
6. 若新增宣導品品項，系統會新增對應配送任務。

### 3.7 接種人數回報

測試步驟：

1. 進入「回報接種人數」。
2. 對已發布場次填寫流感與新冠接種人數。
3. 點選「儲存回報」。

預期結果：

1. `設站資料` 寫入接種人數。
2. 接種率可正確計算。
3. 回報成功後頁面顯示摘要。

### 3.8 里別未設站提醒

測試步驟：

1. 在 `里別清冊` 填入 2 至 3 筆測試資料，例如 `測試區`、`測試里`、`是`。
2. 建立並發布其中 1 個里別的設站資料。
3. 進入「稽催／統計」。
4. 查看「里別未設站提醒」區塊。
5. 點選「產生未設站提醒文字」並複製文字。

預期結果：

1. 清冊里別、已有設站、尚未設站數量正確。
2. 已發布且公開的里別不會列在未設站清單。
3. 尚未設站里別會依行政區列出。
4. 若 `是否啟用` 為 `否`，不應列入統計。
5. 提醒文字不得包含民眾個資、管理碼、Token、Cookie 或憑證。

### 3.9 統計項目檢查

測試步驟：

1. 建立多筆不同行政區的測試設站資料。
2. 至少發布 1 筆資料，並保留 1 筆草稿。
3. 建立至少 1 筆已配送與 1 筆未配送宣導品配送任務。
4. 進入「稽催／統計」。
5. 檢查總場次、已發布、未回報、待配送、配送完成率與行政區設站統計。

預期結果：

1. 配送完成率依未取消配送任務計算。
2. 行政區統計會顯示各行政區全部場次、已發布場次與未回報場次。
3. 未回報場次應與接種人數回報狀態一致。
4. 統計頁不應顯示管理碼、廠商查詢碼、Token、Cookie 或憑證。

### 3.10 防重複送出檢查

測試步驟：

1. 進入任一會呼叫 GAS 的操作，例如新增草稿、發布、回報接種人數或產生提醒文字。
2. 點選送出或執行按鈕後，立即再點其他按鈕。
3. 等待作業完成或故意觸發一筆錯誤資料。

預期結果：

1. 處理期間按鈕會暫時停用。
2. 畫面顯示處理中訊息。
3. 成功或失敗後按鈕會恢復。
4. 不應因連點產生重複資料或重複配送任務。

### 3.11 表單錯誤提示檢查

測試步驟：

1. 在新增設站資料表單故意漏填必填欄位。
2. 在整批上傳貼上缺少必要欄位或時間格式錯誤的假資料。
3. 在接種人數回報輸入非數字。
4. 在宣導品配送任務或廠商回報輸入非數字數量。

預期結果：

1. 錯誤訊息會列出需要修正的問題。
2. 錯誤訊息包含「下一步」提示。
3. 錯誤訊息不得顯示管理碼、Token、Cookie 或憑證。
4. 修正資料後可重新送出。

## 4. 宣導品與廠商測試

### 4.1 發布時產生配送任務

測試步驟：

1. 新增一筆申請宣導品的草稿。
2. 發布該筆資料。
3. 進入「宣導品管理」的「配送任務」分頁。

預期結果：

1. 每個申請品項各產生 1 筆配送任務。
2. 配送任務有 `配送任務ID`。
3. 配送任務狀態預設為 `未配送`。
4. 同一筆接種站重複發布或同一宣導品重複出現在申請品項時，不得產生第二筆未取消配送任務。

### 4.2 修改配送任務

測試步驟：

1. 在「宣導品管理」點選配送任務的「修改」。
2. 填寫預計配送數量、廠商名稱、物流方式與備註。
3. 儲存配送任務。

預期結果：

1. `宣導品配送任務表` 對應列被更新。
2. `最後更新時間` 有更新。
3. `異動紀錄` 有修改配送任務紀錄。

### 4.3 取消配送任務

測試步驟：

1. 在「宣導品管理」點選配送任務的「取消任務」。
2. 確認取消。

預期結果：

1. 配送任務不被刪除。
2. `配送狀態` 改為 `取消`。
3. `異動紀錄` 有取消紀錄。

### 4.4 廠商配送回報

測試步驟：

1. 在「廠商配送回報」輸入測試廠商名稱與測試查詢碼。
2. 查詢配送任務。
3. 點選「回報配送」。
4. 填寫配送狀態、實際配送數量、實際配送日期、物流單號與回報人。
5. 儲存配送回報。

預期結果：

1. 只顯示該廠商的配送任務。
2. 廠商不能修改接種站或配送目的地基本資料。
3. `配送狀態`、`實際配送數量`、`物流單號`、`廠商回報人` 被更新。
4. `廠商回報時間` 有更新。
5. `異動紀錄` 有廠商回報紀錄。

## 5. 通知單 CSV 匯出測試

測試步驟：

1. 建立一筆里別含多個值的測試場次，例如 `測試里、範例里`。
2. 進入「系統工具」。
3. 點選「產生通知單 CSV」。
4. 檢查輸出內容。

預期結果：

1. CSV 有表頭。
2. 同一場次的多個里別會拆成多列。
3. 每列只包含 1 個里別。
4. 不應輸出身分證字號、電話、管理碼、Token、Cookie 或憑證。

## 6. 公開 JSON 測試

測試步驟：

1. 在 Apps Script 執行或從系統工具使用 `buildPublicJson()`。
2. 複製產生的 JSON。
3. 確認只包含已發布且公開資料。
4. 將內容放到 `public/public.json` 測試民眾端。

預期結果：

1. JSON 格式正確。
2. 民眾端可讀取並顯示接種站。
3. 不得輸出內部欄位：
   - 醫療院所十碼代碼
   - 預估人數
   - 接種人數
   - 接種率
   - 填報人
   - 管理碼
   - 宣導品配送資訊

## 7. 民眾端測試

測試步驟：

1. 在本機或 Firebase Hosting 開啟民眾端。
2. 測試今日、明日、本週、附近場次。
3. 測試行政區、里別、日期、關鍵字、疫苗篩選。
4. 測試開啟地圖、複製地址、分享場次。
5. 使用手機瀏覽器測試。
6. 使用 LINE 內建瀏覽器測試。
7. 測試 `queueUrl` 有值、空白與無效網址。
8. 測試 `isOpen = false` 暫停開放狀態。
9. 執行民眾端 RWD 自動驗收：

```powershell
node scripts/rwd-check.mjs
```

預期結果：

1. 查詢條件可正常篩選。
2. 無資料時有下一步提示。
3. 地圖與複製功能可操作。
4. LINE 內建瀏覽器會顯示使用提示。
5. `queueUrl` 有值時顯示叫號或現場資訊按鈕，空白或無效網址時不顯示按鈕。
6. `isOpen = false` 時顯示暫停開放摘要與訊息，不顯示接種站列表。
7. RWD 自動驗收通過，且 `docs/test-evidence/` 產生手機與桌機截圖。

## 8. 失敗紀錄格式

若測試失敗，請記錄：

```text
測試日期：
測試人：
測試項目：
使用假資料：
操作步驟：
預期結果：
實際結果：
錯誤訊息：
截圖檔名：
是否可重現：
備註：
```

## 9. 上線前確認

正式上線前請確認：

1. 測試 Google Sheet 與正式 Google Sheet 分開。
2. 正式資料沒有測試用假資料。
3. `public.json` 不含內部欄位或個資。
4. 管理碼未寫在程式中。
5. 廠商查詢碼由管理者在 Sheet 中維護。
6. Firebase Hosting 使用正式 `public.json`。
7. 已保留可還原的 Git commit。
