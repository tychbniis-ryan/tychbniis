# GAS 實機測試清單

本文件用於 Google Apps Script 與 Google Sheet 實機測試。測試時請使用測試用試算表與假資料，不要使用正式個資、帳密、Token、Cookie 或憑證。

## 1. 測試前準備

1. 建立一份新的 Google Sheet 測試試算表。
2. 建立或開啟綁定該試算表的 Google Apps Script 專案。
3. 將 `gas/Code.gs` 內容貼到 Apps Script 的 `Code.gs`。
4. 將 `gas/Index.html` 內容貼到 Apps Script 的 `Index.html`。
5. 第一次執行 `setupWorkbook()`，並依 Google 提示授權。
6. 確認工作表已建立：
   - `設站資料表`
   - `宣導品品項表`
   - `宣導品配送任務表`
   - `廠商資料表`
   - `系統設定`
   - `異動紀錄`
7. 在 `系統設定` 表設定測試用管理碼。
8. 在 `廠商資料表` 建立測試廠商與測試查詢碼。

## 2. 測試資料原則

測試只能使用假資料，例如：

```text
行政區：測試區
里別：測試里
設站地點名稱：測試活動中心
地址：桃園市測試區測試路 1 號
承接醫療院所名稱：測試診所
醫療院所十碼代碼：0000000000
填報人：測試人員
廠商名稱：測試印刷公司
廠商查詢碼：TEST1234
```

不得使用：

1. 真實民眾姓名。
2. 真實身分證字號。
3. 真實電話。
4. 真實 LINE ID。
5. 正式管理碼。
6. 任何帳密、Token、Cookie 或憑證。

## 3. GAS 後台基本測試

### 3.1 初始化工作表

測試步驟：

1. 在 Apps Script 執行 `setupWorkbook()`。
2. 回到 Google Sheet 檢查工作表與表頭。

預期結果：

1. 必要工作表都存在。
2. 表頭未缺漏。
3. `宣導品品項表` 有測試用初始品項。
4. `系統設定` 有管理功能設定列。

### 3.2 新增草稿設站資料

測試步驟：

1. 部署或預覽 GAS Web App。
2. 進入「新增設站資料」。
3. 使用假資料填完 6 步驟。
4. 選擇「送出草稿」。

預期結果：

1. `設站資料表` 新增 1 筆資料。
2. `資料狀態` 為 `草稿`。
3. `是否公開` 為 `否`。
4. 不應產生宣導品配送任務。

### 3.3 發布設站資料

測試步驟：

1. 進入「維護既有資料」。
2. 找到草稿資料。
3. 點選「發布」。

預期結果：

1. `資料狀態` 為 `已發布`。
2. `是否公開` 為 `是`。
3. `是否鎖定` 為 `是`。
4. 若有申請宣導品，應產生配送任務。
5. `異動紀錄` 有發布紀錄。

### 3.4 申請解鎖與審核

測試步驟：

1. 在「維護既有資料」點選已鎖定資料的「申請解鎖」。
2. 確認表單顯示資料 ID 與場次摘要。
3. 填寫假申請人並送出。
4. 到「稽催／統計」輸入測試管理碼與審核人。
5. 對待審核資料執行「核准解鎖」。

預期結果：

1. 申請後 `解鎖申請狀態` 為 `待審核`。
2. 核准後 `解鎖申請狀態` 為 `已核准`。
3. 核准後 `是否鎖定` 為 `否`。
4. `異動紀錄` 有申請與審核紀錄。

補充測試：

1. 將同一筆接種站的宣導品配送任務狀態改為 `已配送`。
2. 回到「維護既有資料」嘗試申請解鎖。
3. 確認系統阻擋申請，並顯示無法解鎖修改的訊息。
4. 若已有待審核申請，再到「稽催／統計」嘗試核准解鎖。
5. 確認系統阻擋核准。

### 3.5 編輯已解鎖資料

測試步驟：

1. 在「維護既有資料」找到已解鎖資料。
2. 點選「編輯資料」。
3. 修改地址或備註。
4. 點選「儲存修改」。

預期結果：

1. 原資料列被更新。
2. 不會新增第二筆重複資料。
3. `異動紀錄` 有修改紀錄。

### 3.6 接種人數回報

測試步驟：

1. 進入「回報接種人數」。
2. 對已發布場次填寫流感與新冠接種人數。
3. 點選「儲存回報」。

預期結果：

1. `設站資料表` 寫入接種人數。
2. 接種率可正確計算。
3. 回報成功後頁面顯示摘要。

## 4. 宣導品與廠商測試

### 4.1 發布時產生配送任務

測試步驟：

1. 新增一筆申請宣導品的草稿。
2. 發布該筆資料。
3. 進入「宣導品管理」的「配送任務」分頁。

預期結果：

1. 每個申請品項各產生 1 筆配送任務。
2. 配送任務有 `配送任務ID`。
3. 配送任務狀態預設為 `未配送`。

### 4.2 修改配送任務

測試步驟：

1. 在「宣導品管理」點選配送任務的「修改」。
2. 填寫預計配送數量、廠商名稱、物流方式與備註。
3. 儲存配送任務。

預期結果：

1. `宣導品配送任務表` 對應列被更新。
2. `最後更新時間` 有更新。
3. `異動紀錄` 有修改配送任務紀錄。

### 4.3 取消配送任務

測試步驟：

1. 在「宣導品管理」點選配送任務的「取消任務」。
2. 確認取消。

預期結果：

1. 配送任務不被刪除。
2. `配送狀態` 改為 `取消`。
3. `異動紀錄` 有取消紀錄。

### 4.4 廠商配送回報

測試步驟：

1. 在「廠商配送回報」輸入測試廠商名稱與測試查詢碼。
2. 查詢配送任務。
3. 點選「回報配送」。
4. 填寫配送狀態、實際配送數量、實際配送日期、物流單號與回報人。
5. 儲存配送回報。

預期結果：

1. 只顯示該廠商的配送任務。
2. 廠商不能修改接種站或配送目的地基本資料。
3. `配送狀態`、`實際配送數量`、`物流單號`、`廠商回報人` 被更新。
4. `廠商回報時間` 有更新。
5. `異動紀錄` 有廠商回報紀錄。

## 5. 公開 JSON 測試

測試步驟：

1. 在 Apps Script 執行或從系統工具使用 `buildPublicJson()`。
2. 複製產生的 JSON。
3. 確認只包含已發布且公開資料。
4. 將內容放到 `public/public.json` 測試民眾端。

預期結果：

1. JSON 格式正確。
2. 民眾端可讀取並顯示接種站。
3. 不得輸出內部欄位：
   - 醫療院所十碼代碼
   - 預估人數
   - 接種人數
   - 接種率
   - 填報人
   - 管理碼
   - 宣導品配送資訊

## 6. 民眾端測試

測試步驟：

1. 在本機或 Firebase Hosting 開啟民眾端。
2. 測試今日、明日、本週、附近場次。
3. 測試行政區、里別、日期、關鍵字、疫苗篩選。
4. 測試開啟地圖、複製地址、分享場次。
5. 使用手機瀏覽器測試。
6. 使用 LINE 內建瀏覽器測試。

預期結果：

1. 查詢條件可正常篩選。
2. 無資料時有下一步提示。
3. 地圖與複製功能可操作。
4. LINE 內建瀏覽器會顯示使用提示。

## 7. 失敗紀錄格式

若測試失敗，請記錄：

```text
測試日期：
測試人：
測試項目：
使用假資料：
操作步驟：
預期結果：
實際結果：
錯誤訊息：
截圖檔名：
是否可重現：
備註：
```

## 8. 上線前確認

正式上線前請確認：

1. 測試 Google Sheet 與正式 Google Sheet 分開。
2. 正式資料沒有測試用假資料。
3. `public.json` 不含內部欄位或個資。
4. 管理碼未寫在程式中。
5. 廠商查詢碼由管理者在 Sheet 中維護。
6. Firebase Hosting 使用正式 `public.json`。
7. 已保留可還原的 Git commit。
