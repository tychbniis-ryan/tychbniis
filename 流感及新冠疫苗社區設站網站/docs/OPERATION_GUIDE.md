# 日常操作手冊

本文件提供承辦人日常操作流程。若要做正式上線前測試，請改用 `docs/GAS_TEST_CHECKLIST.md`。

## 1. 使用前注意事項

1. 不要在程式或文件中填入正式管理碼、帳密、Token、Cookie 或憑證。
2. 不要在測試資料中填入真實民眾姓名、身分證字號、電話或 LINE ID。
3. 民眾端只應使用 `public.json`，不得直接開放 Google Sheet。
4. 修改已發布資料前，需確認是否已鎖定、是否已有宣導品配送任務。
5. 若畫面顯示錯誤，先截圖並記錄操作步驟，不要重複亂點。
6. 畫面顯示「處理中」時，按鈕會暫時停用，請等待完成後再操作。

## 2. 本機檢查

適用情境：

1. 修改程式後。
2. 貼到 Apps Script 前。
3. 交接給下一位 AI 或承辦人前。

操作方式：

```powershell
node scripts/local-check.mjs
```

預期結果：

1. 顯示 `All local checks passed.`
2. 不會讀寫 Google Sheet。
3. 不會連線 Firebase。
4. 不需要輸入正式管理碼。

## 3. 首次建立工作表

適用情境：

1. 第一次使用系統。
2. 測試用 Google Sheet 尚未建立欄位。
3. 工作表被誤刪或表頭不完整。

操作步驟：

1. 開啟 GAS 後台。
2. 進入「系統工具」。
3. 點選「建立或檢查工作表」。
4. 回到 Google Sheet 確認必要工作表已建立。

預期結果：

1. `設站資料`、`宣導品品項表`、`宣導品配送任務表`、`廠商資料表`、`系統設定`、`異動紀錄` 都存在。
2. 表頭沒有缺漏。
3. `宣導品品項表` 有啟用品項。
4. `里別清冊` 已建立，可由承辦人填入需追蹤的行政區與里別。

## 4. 新增設站資料

操作步驟：

1. 進入「新增設站資料」。
2. 依 6 步驟填寫：
   - 行政區里
   - 日期時間
   - 地點地址
   - 院所疫苗
   - 宣導品
   - 確認送出
3. 送出前檢查摘要。
4. 若尚未確認資料，點「送出草稿」。
5. 若資料已確認可公開，點「送出並發布」。

注意事項：

1. 草稿不會公開到民眾端。
2. 草稿不會產生宣導品配送任務。
3. 發布後會鎖定資料。
4. 若同行政區、里別、日期疑似已有場次，系統會提示可能重複，請人工確認。

## 5. 發布草稿

操作步驟：

1. 進入「維護既有資料」。
2. 找到要發布的草稿。
3. 確認日期、時間、地點、地址、院所與宣導品資料。
4. 點選「發布」。

預期結果：

1. 資料狀態變成 `已發布`。
2. 是否公開變成 `是`。
3. 是否鎖定變成 `是`。
4. 若有申請宣導品，系統會產生配送任務。

## 6. 修改草稿或已解鎖資料

操作步驟：

1. 進入「維護既有資料」。
2. 找到資料。
3. 若畫面有「編輯資料」，表示可修改。
4. 點選「編輯資料」。
5. 修改需要的欄位。
6. 點選「儲存修改」。

注意事項：

1. 編輯模式不會直接發布資料。
2. 草稿如需公開，仍需回到維護頁按「發布」。
3. 已發布且鎖定資料不可直接修改，需先申請解鎖。
4. 已解鎖資料若修改宣導品地址、聯絡資訊、品項或數量，系統會同步更新尚未完成配送的配送任務。

## 7. 申請解鎖

適用情境：

1. 已發布資料需要修正基本欄位。
2. 資料已鎖定，畫面無法直接編輯。

操作步驟：

1. 進入「維護既有資料」。
2. 找到該筆資料。
3. 點選「申請解鎖」。
4. 確認資料 ID 與場次摘要。
5. 填寫解鎖申請人。
6. 視需要填寫解鎖申請原因。
7. 點選「送出解鎖申請」。

預期結果：

1. 解鎖申請狀態變成 `待審核`。
2. 管理者可於「稽催／統計」審核。

## 8. 管理者審核解鎖

操作步驟：

1. 進入「稽催／統計」。
2. 若畫面要求管理作業驗證，先輸入管理碼。
3. 在解鎖審核區輸入管理碼與審核人。
4. 找到待審核申請。
5. 依實際情況點選「核准解鎖」或「退回申請」。

注意事項：

1. 管理碼應在 Google Sheet「系統設定」維護，不應寫在程式碼。
2. 若該筆資料已有宣導品配送完成，修改前應特別確認配送紀錄是否會受影響。
3. 若該筆資料已有狀態為 `已配送` 的宣導品配送任務，系統會阻擋申請解鎖與核准解鎖。

## 9. 進入管理作業

需要管理碼的頁面：

1. 稽催／統計。
2. 宣導品管理。
3. 系統工具。

操作步驟：

1. 在首頁點選上述管理作業。
2. 看到「管理作業驗證」後輸入管理碼。
3. 點選「驗證並進入」。
4. 驗證通過後，本次頁面工作階段可進入其他管理頁。

注意事項：

1. 管理碼應由管理者在 Google Sheet「系統設定」維護。
2. 不要把正式管理碼貼在文件、截圖或對話中。
3. 廠商配送回報不需要管理碼，仍使用廠商名稱與廠商查詢碼。

## 10. 查看里別未設站提醒

適用情境：

1. 要確認哪些里別尚未建立已發布且公開的設站資料。
2. 要產生可貼到 LINE 或內部工作群組的提醒文字。

操作步驟：

1. 先到 Google Sheet 的 `里別清冊` 維護行政區與里別。
2. 需要追蹤的里別，`是否啟用` 請填 `是` 或留白。
3. 暫時不用追蹤的里別，`是否啟用` 請填 `否`。
4. 進入「稽催／統計」。
5. 查看「里別未設站提醒」。
6. 點選「產生未設站提醒文字」。
7. 點選「複製文字」後貼到需要提醒的地方。

注意事項：

1. 系統只把 `已發布` 且 `是否公開 = 是` 的場次視為已有設站。
2. 若同一場次填了多個里別，系統會拆開比對。
3. `里別清冊` 不應填入民眾姓名、電話、身分證字號或其他個資。

## 11. 查看統計資料

操作步驟：

1. 進入「稽催／統計」。
2. 通過管理作業驗證。
3. 查看上方統計卡片。
4. 查看「行政區設站統計」。

統計內容：

1. 全部場次。
2. 已發布場次。
3. 未回報場次。
4. 待配送宣導品任務。
5. 宣導品配送完成率。
6. 各行政區全部場次、已發布場次與未回報場次。

注意事項：

1. 統計資料來自目前 Google Sheet 內容。
2. 若剛修改資料但畫面未更新，請回首頁後重新進入「稽催／統計」。
3. 統計畫面不得截圖外流管理碼或內部設定。

## 12. 下架資料

操作步驟：

1. 進入「維護既有資料」。
2. 找到要下架的資料。
3. 點選「下架」。
4. 依畫面提示確認。

預期結果：

1. 民眾端不再顯示該場次。
2. 內部資料仍保留。
3. 異動紀錄會保留下架紀錄。

## 13. 回報接種人數

操作步驟：

1. 進入「回報接種人數」。
2. 找到要回報的場次。
3. 填寫流感疫苗接種人數與新冠疫苗接種人數。
4. 視需要填寫備註。
5. 點選「儲存回報」。

注意事項：

1. 人數請填 0 或正整數。
2. 若回報數超過預估數，系統會提醒確認。
3. 成功後畫面會顯示回報摘要。

## 14. 宣導品管理

### 14.1 查看配送任務

操作步驟：

1. 進入「宣導品管理」。
2. 選擇「配送任務」分頁。
3. 查看任務狀態、品項、地點與廠商。

### 14.2 修改配送任務

操作步驟：

1. 在配送任務卡片點選「修改」。
2. 修改配送狀態、數量、日期、廠商、物流或備註。
3. 點選「儲存配送任務」。

注意事項：

1. 數量請填 0 或正整數。
2. 修改會寫入異動紀錄。

### 14.3 取消配送任務

操作步驟：

1. 在配送任務卡片點選「取消任務」。
2. 確認取消。

預期結果：

1. 任務不會被刪除。
2. 配送狀態會改為 `取消`。

### 14.4 新增非接種站配送

操作步驟：

1. 進入「宣導品管理」。
2. 選擇「非接種站配送」分頁。
3. 填寫行政區、地點、地址、聯絡人、宣導品與數量。
4. 點選「建立配送任務」。

## 15. 廠商配送回報

操作步驟：

1. 進入「廠商配送回報」。
2. 輸入廠商名稱與廠商查詢碼。
3. 點選「查詢任務」。
4. 找到配送任務後點選「回報配送」。
5. 填寫配送狀態、實際配送數量、日期、物流方式、物流單號與回報人。
6. 點選「儲存配送回報」。

注意事項：

1. 廠商只能回報配送欄位。
2. 廠商不能修改接種站或配送目的地基本資料。
3. 查詢碼由管理者在 Google Sheet「廠商資料表」維護。

## 16. 產生 public.json

操作步驟：

1. 確認需要公開的資料都已發布。
2. 進入「系統工具」。
3. 點選「產生 public.json 內容」。
4. 複製產生的 JSON。
5. 放入民眾端 `public/public.json`。

檢查重點：

1. 只輸出已發布且公開資料。
2. 不包含內部欄位。
3. 不包含管理碼、填報人、接種人數、宣導品配送資訊。

## 17. 更新民眾端

操作步驟：

1. 更新 `public/public.json`。
2. 在本機開啟民眾端測試。
3. 確認今日、明日、本週、行政區、日期與關鍵字查詢。
4. 確認地圖、複製地址、分享場次可操作。
5. 確認無資料時有提示。
6. 確認無誤後再部署 Firebase Hosting。

部署指令：

```powershell
firebase deploy --only hosting
```

## 18. 常見狀況

### 18.1 找不到資料

處理方式：

1. 確認是否已發布。
2. 確認是否公開。
3. 確認日期與查詢條件是否正確。
4. 確認 `public.json` 是否已更新。

### 18.2 無法編輯已發布資料

原因：

1. 已發布資料會鎖定。

處理方式：

1. 先申請解鎖。
2. 管理者核准後再編輯。

### 18.3 廠商查不到任務

處理方式：

1. 確認廠商名稱是否與 `廠商資料表` 完全一致。
2. 確認廠商查詢碼是否正確。
3. 確認配送任務是否已指定該廠商名稱。
4. 確認廠商狀態是否啟用。

### 18.4 民眾端資料未更新

處理方式：

1. 重新產生 `public.json`。
2. 確認 `public/public.json` 已替換。
3. 重新部署 Firebase Hosting。
4. 清除瀏覽器快取後再測。

## 19. 發生錯誤時怎麼記錄

請記錄：

```text
日期：
操作人：
功能頁面：
操作步驟：
畫面錯誤訊息：
資料ID或配送任務ID：
是否可重現：
截圖檔名：
備註：
```

不要貼上正式管理碼、帳密、Token、Cookie、憑證或完整個資。

## 20. 還原方式

若這次更新後出現問題，可先判斷是資料問題或程式問題。

資料問題：

1. 不要刪除整張表。
2. 先複製有問題的資料列到備份分頁。
3. 再依異動紀錄修正欄位。

程式問題：

1. 回到 Git 版本紀錄。
2. 找到上一個可用 commit。
3. 使用 `git revert` 還原有問題的 commit。
4. 重新貼上 GAS 程式或重新部署民眾端。
