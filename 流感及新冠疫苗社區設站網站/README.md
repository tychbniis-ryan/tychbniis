# 流感及新冠疫苗社區設站網站

本專案用於建置「桃園市流感及新冠疫苗接種站」填報與民眾查詢系統。

第一版採用：

1. Google Sheet 作為資料來源。
2. Google Apps Script 作為填報端與 JSON 產生工具。
3. Firebase Hosting 作為民眾端靜態查詢網站。
4. `public/public.json` 作為民眾端唯一公開資料來源。

## 民眾端功能

1. 讀取 `public.json`。
2. 顯示標題、公告、更新時間。
3. 今日、明日、本週、附近場次快速查詢。
4. 行政區、里別、日期、關鍵字、疫苗篩選。
5. 卡片式顯示接種站資料。
6. 開啟 Google 地圖；若公開資料未填 `mapUrl`，民眾端會用地址或地點名稱產生 Google Maps 搜尋連結。
7. 複製地址。
8. 複製場次資訊，方便貼到 LINE。
9. 分享場次資訊，支援手機瀏覽器 Web Share API。
10. 支援 `siteId`、`district`、`village`、`date`、`keyword`、`source` 網址參數。
11. 支援 `public.json` 的 `defaultView` 預設查詢模式。
12. 支援 `queueUrl` 叫號／現場資訊連結；只有 `http://` 或 `https://` 完整網址才會顯示按鈕。
13. 支援 `isOpen = false` 暫停開放狀態，會顯示暫停訊息並清空查詢結果。

## GAS 功能

1. 初始化 Google Sheet 工作表。
2. 新增設站資料。
3. 整批新增，上限 100 筆。
4. 維護既有資料。
5. 發布、鎖定、下架。
6. 申請解鎖、管理者審核解鎖。
7. 回報接種人數。
8. 稽催／統計與 LINE 文字產生。
9. 里別未設站提醒。
10. 宣導品品項初始化。
11. 發布時自動產生宣導品配送任務。
12. 非接種站配送任務新增。
13. 廠商查詢碼登入與配送回報。
14. 簡易通知單 CSV 匯出。
15. 產生公開 JSON。
16. 寫入異動紀錄。

## GAS 後台頁面

`gas/Index.html` 目前提供以下入口：

1. 新增設站資料。
2. 維護既有資料。
3. 回報接種人數。
4. 查詢場次。
5. 稽催／統計。
6. 宣導品管理。
7. 廠商配送回報。
8. 系統工具。

首頁入口分為「主要作業」與「管理作業」。新增資料表單採 6 步驟流程：

1. 行政區里。
2. 日期時間。
3. 地點地址。
4. 院所疫苗。
5. 宣導品。
6. 確認送出。

管理作業中的「稽催／統計」、「宣導品管理」與「系統工具」需先輸入管理碼才能進入。管理碼由 GAS 後端讀取 Google Sheet「系統設定」工作表，不寫死在程式中。「廠商配送回報」維持廠商名稱與廠商查詢碼流程，不要求管理碼，避免廠商無法回報配送狀態。

GAS 後台呼叫後端作業時，畫面按鈕會暫時停用並顯示處理中訊息，避免連續點擊造成重複送出；成功或失敗後會恢復按鈕。

GAS 後台表單錯誤會以清單顯示問題，並附上「下一步」提示，讓填報人知道要回到哪個欄位或按鈕重新操作。

若設站資料包含叫號或現場資訊連結，`叫號連結` 必須填寫 `http://` 或 `https://` 開頭的完整網址。空白可接受；不合法網址會被阻擋或不顯示於民眾端。

新增資料表單使用 `localStorage` 暫存，送出成功後會清除暫存。若偵測到暫存資料，畫面會提示恢復或清除。送出前會先檢查必填欄位、接種日期、設站時間格式與預估人數格式，後端也會阻擋不存在日期與不合法時間區間，並顯示確認摘要。最後可選擇「送出草稿」或「送出並發布」。

送出前會以目前已載入資料輔助比對「行政區 + 里別 + 接種日期」。若同一里別同日已有場次，會提示可能重複，並提供「仍要新增」或「返回修改」。此檢查是前端輔助提醒，正式資料仍需以 Google Sheet 內容與人工確認為準。

GAS 後端也會檢查「行政區 + 里別 + 接種日期」是否已有未下架資料。若判斷為重複，會阻擋新增或修改，避免繞過 UI 或重複送出造成重複場次。

維護頁可對未鎖定資料使用「編輯資料」。編輯模式沿用 6 步驟表單並呼叫 `updateSite()` 更新既有資料，不會建立新資料。草稿發布仍需回到維護頁按「發布」，以確保鎖定與宣導品配送任務流程一致。

維護頁的「申請解鎖」會開啟頁面內表單，帶入資料 ID 與場次摘要。填報人需填寫解鎖申請人，解鎖申請原因可視需要填寫；送出後由管理者於「稽催／統計」頁審核。

若該場次已有宣導品配送任務狀態為 `已配送`，系統會阻擋申請解鎖與核准解鎖，避免配送紀錄與接種站基本資料不一致。

已解鎖資料儲存修改後，系統會同步更新該接種站尚未完成配送的宣導品任務。同步範圍包含配送地址、聯絡人、電話、備註、品項與數量；已配送任務不會被修改。

宣導品申請會讀取「宣導品品項表」中啟用的品項，於第 5 步顯示為勾選項目與數量欄位。送出前系統會整理回既有欄位 `宣導品申請品項`、`宣導品申請數量`，以維持目前 Google Sheet 結構。

系統產生宣導品配送任務時，會以接種站資料 ID 與宣導品 ID 防止重複建立；同一場次同一宣導品已有未取消任務時，不會再新增第二筆。

「稽催／統計」頁提供解鎖審核區塊。管理者需輸入管理碼與審核人後，才能對待審核申請執行「核准解鎖」或「退回申請」。管理碼仍由 GAS 後端讀取「系統設定」工作表驗證，不寫死於程式。

「稽催／統計」頁也提供里別未設站提醒、宣導品配送完成率與行政區設站統計。系統會讀取 Google Sheet「里別清冊」中啟用的行政區與里別，比對目前已發布且公開的設站資料，列出尚未設站里別並產生可複製文字。承辦人只需在「里別清冊」維護行政區、里別與是否啟用，不需修改程式。

新增頁提供整批上傳區塊，可貼上含表頭的 TSV 或簡易 CSV 資料。單次最多 100 筆，送出前會檢查必要欄位、接種日期、設站時間格式與人數格式。後端會再次驗證日期與時間，整批資料不得包含帳密、Token、Cookie、身分證字號或其他不應進入設站資料表的個資。

回報接種人數頁會顯示流感與新冠預估人數。若接種人數超過預估人數，系統會提醒填報人確認後仍可送出；若輸入非數字，會阻擋送出。接種人數空白時接種率維持空白；明確填寫 `0` 時才會顯示 `0%`。回報成功後會顯示本次回報摘要。

查詢場次頁支援行政區、里別、單日或日期區間、設站地點、承接醫療院所、服務對象、疫苗廠牌、是否公開、資料狀態、回報狀態、宣導品配送狀態與關鍵字篩選。

宣導品管理頁採分頁操作，分為「配送任務」、「非接種站配送」與「品項管理」。配送任務可透過頁面表單修改配送狀態、配送數量、配送日期、廠商資訊、物流資訊與備註，也可將任務狀態改為 `取消`。系統不提供真刪除，修改與取消均會寫入異動紀錄。品項管理目前提供啟用品項檢視與建立或檢查工作表入口，新增或調整品項仍建議於 Google Sheet「宣導品品項表」處理。

廠商配送回報頁會先以廠商名稱與查詢碼查詢任務。廠商點選「回報配送」後，使用頁面內表單填寫配送狀態、實際配送數量、日期、物流資訊、回報人與備註；廠商不得修改接種站或配送目的地基本資料。

系統工具可產生通知單 CSV。若同一筆場次包含多個里別，匯出時會拆成單一里別一列，方便後續套印或人工整理。

## 本機測試

檢查 GAS 語法、GAS 回報接種人數頁手機友善結構、民眾端 JSON 與核心邏輯假資料測試：

```powershell
node scripts/local-check.mjs
```

此指令不會讀寫 Google Sheet，不會連線到 Firebase，也不需要管理員權限。

檢查民眾端手機與桌機版面：

```powershell
node scripts/rwd-check.mjs
```

此指令會在本機啟動暫時的靜態伺服器，檢查水平溢位與按鈕觸控高度，並將截圖輸出到 `docs/test-evidence/`。

在本資料夾執行：

```powershell
python -m http.server 5173 -d public
```

開啟：

```text
http://localhost:5173
```

若電腦沒有 Python，可直接用 VS Code Live Server 或其他靜態伺服器開啟 `public` 資料夾。

## Firebase 部署

確認已安裝 Firebase CLI 並登入後，在本資料夾執行：

```powershell
firebase deploy --only hosting
```

正式部署前請先確認：

1. `public/public.json` 已由 GAS 產生，且不含內部欄位。
2. 民眾端不顯示醫療院所十碼代碼、預估人數、接種人數、接種率、填報人、內部狀態、宣導品配送資訊。
3. 範例資料已替換為正式公開資料。

## GAS 使用方式

1. 開啟 Google Apps Script 專案。
2. 將 `gas/Code.gs` 貼入或同步為 `Code.gs`。
3. 將 `gas/Index.html` 貼入或同步為 `Index.html`。
4. 第一次執行 `setupWorkbook()` 建立工作表。
5. 部署 Web App 後，填報人員可進入後台新增資料。
6. 使用 `buildPublicJson()` 產生公開 JSON 內容。

注意：本機只能檢查語法與靜態頁面。`SpreadsheetApp`、`HtmlService`、`DriveApp` 相關功能需在 Google Apps Script 測試專案內驗證。

## 資安注意事項

1. 不要把管理碼、帳密、Token、Cookie 寫進程式。
2. 管理碼應放在 Google Sheet 的「系統設定」工作表。
3. 民眾端不得讀取 Google Sheet 原始資料。
4. 民眾端不得要求民眾提供姓名、電話、身分證字號或 LINE ID。
5. 定位僅於前端當次排序使用，不儲存、不回寫。
