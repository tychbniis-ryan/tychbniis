# 前台填報端與宣導品管理開發文件 v4

## 1. 文件目的

本文件提供 AI／開發者建置「流感及新冠疫苗設站填報系統」之規格依據，範圍包含：

1. 接種站基本資料新增與維護。
2. 手機端回報流感及新冠疫苗接種人數。
3. 查詢與稽催／統計功能。
4. 宣導品申請、配送任務自動產生、廠商配送回報。
5. 異動紀錄、本機暫存、整批上傳與簡易匯出。

系統架構為：

```text
填報端：Google Apps Script Web App
資料庫：Google Sheet
民眾查詢端：Firebase Hosting
公開資料：由 GAS 產生 JSON
```

---

## 2. 使用角色

| 角色 | 使用目的 | 主要裝置 |
|---|---|---|
| 衛生所／接種站填報人員 | 新增設站資料、申請宣導品、回報接種人數、查詢場次 | PC、手機 |
| 管理者 | 維護資料、發布、審核解鎖、稽催、統計、宣導品管理、匯出資料 | PC |
| 廠商 | 查詢配送任務、回報配送狀態與物流資訊 | 手機、PC |
| 民眾 | 於 Firebase 前台查詢已公開設站資訊 | 手機為主 |

## 5. 新增功能

### 5.1 操作流程

新增功能採分步驟設計：

```text
第 1 步：選擇行政區
第 2 步：複選里別
第 3 步：填寫接種日期、設站時間、地點、地址
第 4 步：填寫承接院所、服務對象、疫苗廠牌、預估人數
第 5 步：填寫宣導品申請資料
第 6 步：確認資料並加入待上傳清單或送出
```

### 5.2 里別與廠牌規則

| 項目 | 規則 |
|---|---|
| 里別 | 可複選，儲存時以「、」串接，例如 `南華里、西湖里` |
| 服務對象 | 可複選，儲存時以「、」串接 |
| 流感疫苗廠牌 | 可複選，儲存時以「、」串接 |
| 新冠疫苗廠牌 | 可複選，儲存時以「、」串接 |

### 5.3 重複資料提醒

新增時檢查：

```text
行政區 + 里別 + 接種日期
```

不納入設站地點名稱，因地點可能有差異字。

若複選多個里別，系統應逐一比對。例如選擇 `南華里、西湖里`，需分別檢查：

```text
桃園區 + 南華里 + 接種日期
桃園區 + 西湖里 + 接種日期
```

若已有場次，提示：

```text
系統偵測到以下里別於該日期已有設站資料：
南華里：已有 1 筆場次
西湖里：已有 2 筆場次
請確認是否仍要新增。
```

按鈕：

```text
仍要新增
返回修改
```

### 5.4 新增資料預設值

| 欄位 | 預設值 |
|---|---|
| 資料狀態 | 草稿 |
| 是否公開 | 否 |
| 是否鎖定 | 否 |
| 是否申請宣導品 | 否 |

草稿一律不得公開。

## 6. 發布、鎖定與解鎖

### 6.1 發布功能

使用者可於維護頁面點擊「發布」。發布後：

1. 資料狀態改為 `已發布`。
2. 是否鎖定改為 `是`。
3. 鎖定時間由系統自動帶入。
4. 基本設站資料鎖定。
5. 宣導品申請資料鎖定。
6. 使用者僅可回報流感與新冠疫苗接種人數。
7. 若有申請宣導品且資料完整，系統同步產生宣導品配送任務。
8. 寫入異動紀錄。

### 6.2 發布後可修改欄位

發布且鎖定後，使用者只能修改：

```text
流感疫苗接種人數
新冠疫苗接種人數
接種回報備註
填報單位
填報人
```

不得修改：

```text
行政區、里別、日期、時間、地點、地址、院所、服務對象、疫苗廠牌、預估人數、是否公開、宣導品申請資料
```

### 6.3 申請解鎖流程

使用者於維護頁面點擊「申請解鎖」。

申請解鎖欄位：

```text
解鎖申請人：必填
解鎖申請原因：非必填
```

送出後主資料表更新：

```text
解鎖申請狀態 = 待審核
解鎖申請時間 = 系統時間
解鎖申請人 = 使用者填寫
解鎖申請原因 = 使用者填寫，可空白
```

### 6.4 管理者審核解鎖

管理者於後台輸入管理碼後，進入「解鎖審核」頁面。

可操作：

```text
核准解鎖
退回申請
```

核准後：

```text
是否鎖定 = 否
解鎖申請狀態 = 已核准
解鎖審核時間 = 系統時間
解鎖審核人 = 管理者填寫
解鎖時間 = 系統時間
```

退回後：

```text
解鎖申請狀態 = 已退回
```

### 6.5 已配送宣導品不得解鎖

若該接種站已產生宣導品配送任務，且任一相關配送任務狀態為 `已配送`，則不得解鎖。

提示文字：

```text
本筆資料已有宣導品配送任務完成配送，為避免配送紀錄異動，無法解鎖修改。
```

若配送任務狀態為 `未配送`、`配送中`、`異常`，管理者核准解鎖後，可修改資料；修改後配送任務需依規則同步異動並寫入異動紀錄。

## 7. 宣導品申請與配送任務

### 7.1 宣導品申請規則

「是否申請宣導品」為必填，預設 `否`。

若選擇 `是`，需填寫：

```text
宣導品申請品項
各品項申請數量
宣導品配送聯絡人
宣導品配送聯絡電話
宣導品配送地址
```

配送地址預設帶入接種站地址，可修改。

### 7.2 宣導品數量結構化

使用者不得以自由文字填寫總量。應由系統依品項顯示數字欄位。

畫面範例：

```text
是否申請宣導品：［需要］［不需要］

☑ 流感疫苗宣導海報　數量：___ 張
☑ 流感疫苗接種提醒單張　數量：___ 份
☑ 新冠疫苗宣導單張　數量：___ 份
☑ 疫苗設站宣導布條　數量：___ 條
```

規則：

1. 宣導品品項來自「宣導品品項表」。
2. 僅顯示 `是否啟用 = 是` 的品項。
3. 勾選品項後，該品項數量必填。
4. 數量只能輸入 0 或正整數。
5. 若數量為 0，視為不申請該品項。
6. 發布時每個品項產生一筆配送任務。

### 7.3 草稿不產生配送任務

草稿狀態不產生配送任務，避免草稿資料造成配送錯誤。

### 7.4 發布時自動產生配送任務

當資料發布時，若：

```text
是否申請宣導品 = 是
且宣導品申請資料完整
```

系統應自動依每個申請品項產生一筆宣導品配送任務。

接種站配送不需要管理者再額外建立配送任務。

### 7.5 防止重複產生配送任務

發布或解鎖後重新發布時，需檢查：

```text
來源資料ID + 宣導品ID + 配送狀態未取消
```

若已存在，不新增重複任務，而是依狀態更新原任務。

### 7.6 解鎖後配送任務同步規則

| 情境 | 系統處理 |
|---|---|
| 修改配送地址、聯絡人、電話 | 同步更新未配送／配送中／異常任務 |
| 修改宣導品數量 | 同步更新申請數量與預計配送數量 |
| 新增宣導品品項 | 新增對應配送任務 |
| 取消宣導品品項 | 對應配送任務改為取消 |
| 任一配送任務已配送 | 不得解鎖，因此不得修改 |

修改前需提示：

```text
本筆資料已產生宣導品配送任務，修改後將同步更新相關配送任務，是否確認？
```

## 9. 非接種站宣導品配送

只有非接種站配送才需要透過「宣導品管理」手動新增。

流程：

```text
進入宣導品管理
新增非接種站配送任務
填寫地點類型、行政區、地點名稱、地址、聯絡人、電話

```

非接種站任務之 `是否關聯接種站 = 否`，`關聯接種站資料ID` 留空。

預設顯示：


### 11.2 接種數規則

| 項目 | 規則 |
|---|---|
| 流感疫苗接種人數 | 0 或正整數 |


## 14. 稽催／統計

稽催／統計為首頁第一層功能，需輸入管理碼。

### 14.1 未填報提醒

未填報定義：

```text
若流感疫苗預估人數 > 0 且流感疫苗接種人數空白，視為流感未填報。
若新冠疫苗預估人數 > 0 且新冠疫苗接種人數空白，視為新冠未填報。
兩者皆無預估人數者，不列入未填報。
```

需提供 LINE 文字產生與複製功能。

### 14.2 里別未設站提醒

比對：

```text
里別明細表啟用里別 - 主資料表已發布／已完成場次里別
```

多里別以「、」拆分後比對。

### 14.3 統計項目

| 統計 | 說明 |
|---|---|
| 接種率 < 50% 清單 | 流感、新冠分開統計 |
| 接種率統計 | 全市、行政區、場次 |
| 設站數統計 | 全市、行政區、日期 |
| 宣導品配送完成率 | 全部、行政區、廠商、品項 |

## 15. 匯出功能，第 1 版納入

第 1 版需提供簡易匯出功能，供使用者套印通知單使用。

### 15.1 匯出欄位

匯出資料包含：

```tsv
行政區	里別	設站地點	接種日期	設站時間
```

### 15.2 單一里別處理

因主資料表里別可能為多里別串接，例如：

```text
南華里、西湖里
```

匯出時需拆成單一里別一列。

範例：

| 行政區 | 里別 | 設站地點 | 接種日期 | 設站時間 |
|---|---|---|---|---|
| 桃園區 | 南華里 | 南門市民活動中心 | 115/10/1 | 0800-1200 |
| 桃園區 | 西湖里 | 南門市民活動中心 | 115/10/1 | 0800-1200 |

### 15.3 匯出格式

第 1 版可提供：

```text
CSV
```

或直接產生可複製表格。若開發容易，可另提供 `.xlsx` 匯出。

## 19. 本機暫存

使用 localStorage 或同等前端暫存機制。

適用：

```text
新增資料
維護修改
回報接種資料
整批新增
整批回報
整批維護
```

送出成功後清除暫存。

若偵測到暫存資料，提示：

```text
系統偵測到尚未送出的暫存資料，是否恢復？
```

按鈕：

```text
恢復資料
清除暫存
```

不輸出：
