# 流感及新冠疫苗設站填報與民眾查詢網站
# 前端 UI/UX 設計與介面開發文件 v2

## 1. 文件目的

本文件接續既有「流感及新冠疫苗設站填報與民眾查詢網站整體架構開發文件」及「前台填報端與宣導品管理開發文件」，重新整理前端網站之 UI/UX 設計方向、介面元件、互動流程與 RWD 響應式規格，供前端開發者、Google Apps Script 開發者及 Firebase Hosting 前台建置時使用。

本文件定位為「可執行的介面開發規格」，不是單純的功能清單。開發時應依本文件建立一致的視覺語言、操作流程與元件樣式，使系統具備公共服務網站的可信任感，同時兼顧衛生所人員、管理者、廠商及民眾在手機與電腦上的實際使用需求。

---

## 2. 設計定位

本系統不是形象宣傳網站，而是具備「公共服務查詢」與「現場填報作業」性質的業務系統。設計重點不在視覺華麗，而在於讓民眾快速查詢、讓衛生所快速填報、讓管理者快速掌握狀態。

整體 UI 應避免過度裝飾，採用清楚的資訊層級、穩定的色彩系統、明確的操作按鈕與一致的狀態標籤。

### 2.1 核心風格

```text
公共服務網站 × 醫療疫苗資訊 × 行動填報工具
```

### 2.2 視覺關鍵字

```text
清楚、可信任、穩定、親和、低干擾、手機友善
```

### 2.3 應避免的設計風格

開發時應避免下列容易產生「AI 生成感」或不符合公共服務網站的設計：

1. 大面積藍紫漸層背景。
2. 過多插圖、emoji 或裝飾性 icon。
3. 每個區塊都使用過重陰影或過大圓角。
4. 使用空泛標語取代實際操作說明。
5. 按鈕顏色過多，無法判斷主次操作。
6. 文字密度過高，將 Google Sheet 表格直接搬上網頁。
7. 手機版仍使用大型橫向表格，導致必須左右滑動。

## 5. Design Tokens 設計規格

本章節作為前端 CSS 變數或樣式設定依據。

### 5.1 色彩系統

#### 5.1.1 主色與輔色

| Token | 色碼 | 用途 |
|---|---|---|
| `--color-primary` | `#1F6FB2` | 主按鈕、連結、目前選取狀態 |
| `--color-primary-dark` | `#16324F` | 頁面標題、重要文字 |
| `--color-primary-light` | `#E8F2FB` | 淺藍背景、提示區塊 |
| `--color-health-green` | `#2F855A` | 成功、已發布、已回報、已配送 |
| `--color-warning` | `#B7791F` | 待回報、待審核、需確認 |
| `--color-danger` | `#C53030` | 錯誤、下架、取消、異常 |
| `--color-bg` | `#F6F8FA` | 頁面背景 |
| `--color-surface` | `#FFFFFF` | 卡片、表單區塊 |
| `--color-border` | `#D8DEE6` | 邊框、分隔線 |
| `--color-text` | `#1F2937` | 主要文字 |
| `--color-text-muted` | `#64748B` | 輔助文字、更新時間、備註 |

#### 5.1.2 色彩使用原則

1. 民眾端以白底、淺灰背景、藍色主視覺為主。
2. 填報端可增加中性灰與表格線條，提高作業效率。
3. 管理功能可以提高資訊密度，但不得犧牲可讀性。
4. 狀態顏色需全系統一致。
5. 不得只靠顏色傳達狀態，需搭配文字標籤。

### 5.2 字體系統

本系統中文字體建議採用「思源黑體」與「思源宋體」雙字體策略。

#### 5.2.1 主要介面字體

```css
font-family: "Source Han Sans TC", "Noto Sans TC", "Microsoft JhengHei", sans-serif;
```

適用範圍：

1. 按鈕。
2. 表單欄位。
3. 查詢條件。
4. 卡片資料。
5. 表格內容。
6. 狀態標籤。
7. 系統提示訊息。

使用理由：思源黑體適合螢幕閱讀，字形中性、清楚、現代，適合作為政府服務網站及業務系統的主要 UI 字體。

#### 5.2.2 輔助正式文字字體

```css
font-family: "Source Han Serif TC", "Noto Serif TC", serif;
```

適用範圍：

1. 首頁公告中較正式的提醒文字。
2. 民眾端重要說明。
3. 列印或匯出通知單標題。
4. 需要較正式、文書感的段落。

使用原則：思源宋體不建議大量用於表單、按鈕與密集資料，避免降低螢幕閱讀效率。建議僅作為重點公告或正式文字輔助。

#### 5.2.3 字級規格

| 元件 | 桌機版 | 手機版 | 字重 |
|---|---:|---:|---:|
| 頁面主標題 | 28px / 36px | 24px / 32px | 700 |
| 區塊標題 | 22px / 30px | 20px / 28px | 700 |
| 卡片標題 | 20px / 28px | 18px / 26px | 700 |
| 重要資訊，例如日期時間 | 22px / 30px | 20px / 28px | 700 |
| 一般內文 | 16px / 24px | 16px / 24px | 400 |
| 表單標籤 | 15px / 22px | 15px / 22px | 600 |
| 輔助說明 | 14px / 20px | 14px / 20px | 400 |
| 錯誤訊息 | 14px / 20px | 14px / 20px | 600 |
| 狀態標籤 | 13px / 18px | 13px / 18px | 600 |

### 5.3 間距系統

| Token | 數值 | 用途 |
|---|---:|---|
| `--space-1` | 4px | 小間距、icon 與文字間距 |
| `--space-2` | 8px | 標籤間距、表單說明間距 |

| 元件 | 圓角 | 陰影 |

### 5.5 狀態標籤

| 狀態 | 顏色 | 使用情境 |

## 6. 共用元件規格

### 6.1 Header 頁首

#### 填報端

```text
桃園市流感及新冠疫苗設站填報系統
填報管理端
```

右側可放：

```text
回到首頁｜操作說明｜資料更新時間
```

#### 民眾端

```text
桃園市流感及新冠疫苗接種站查詢
桃園市政府衛生局
```

民眾端 Header 應簡潔，不放過多後台操作連結。

### 6.2 Footer 頁尾

```text
桃園市政府衛生局
資料更新時間：115/10/01 17:00
接種資訊依里辦公處、轄區衛生所或現場公告為準。
```

### 6.3 Button 按鈕

| 類型 | 樣式 | 用途 |
|---|---|---|
| Primary | 藍底白字 | 查詢、下一步、送出、儲存 |
| Secondary | 白底藍字、藍框 | 返回、清除條件、複製地址 |
| Success | 綠底白字 | 發布、完成配送 |
| Warning | 橘底或橘框 | 申請解鎖、仍要新增 |
| Danger | 紅底或紅框 | 下架、取消、刪除暫存 |
| Ghost | 透明背景 | 次要輔助操作 |

手機版主要按鈕高度不得低於 44px，建議 48px。

### 6.4 Form Field 表單欄位

表單欄位需包含：

```text
欄位標籤
必填標示
輸入框
格式提示
錯誤訊息
```

範例：

```text
設站時間（必填）
[ 0800-1200 ]
請輸入 4 位數開始時間與結束時間，例如 0800-1200。
```

錯誤訊息範例：

```text
請輸入正確時間格式，例如 0800-1200。
```

### 6.5 Alert 提醒區塊

| 類型 | 用途 |
|---|---|
| Info | 一般說明、接種提醒 |
| Warning | 可能有重複資料、接種人數超過預估 |
| Error | 必填未填、格式錯誤 |
| Success | 儲存成功、回報完成 |

提醒文字不得只寫「錯誤」或「失敗」，需說明下一步。

### 6.6 Card 卡片

卡片主要用於：

1. 民眾端查詢結果。
2. 手機版維護列表。
3. 回報場次。
4. 宣導品配送任務。
5. 首頁功能入口。

卡片資訊層級應固定，避免每張卡片顯示順序不同。

### 6.7 Table 表格

PC 管理端可使用表格，但需符合：

1. 重要欄位靠左。
2. 操作欄固定於最右側。
3. 狀態欄使用文字標籤。
4. 表格上方需有篩選條件。
5. 手機版不得直接顯示大型表格，應轉為卡片。

### 6.8 Empty State 無資料畫面

不要只顯示「查無資料」。

建議文字：

```text
目前查無符合條件的接種站資料。
您可以清除篩選條件，或改查其他行政區與日期。
```

按鈕：

```text
[清除篩選條件] [查看本週全部場次]
```

## 7. 民眾端 Firebase 查詢網站 UI

### 7.1 頁面目標

民眾端目標是讓民眾或家屬快速查到：

1. 哪一天可以接種。
2. 在哪裡接種。
3. 幾點開始與結束。
4. 服務對象為何。
5. 提供哪些疫苗。
6. 是否有重要備註。

### 7.2 民眾端首頁架構

```text
頁首
  ↓
主標題與更新時間
  ↓
提醒公告
  ↓
查詢條件區
  ↓
快速篩選
  ↓
結果摘要
  ↓
接種站卡片列表
  ↓
頁尾
```

### 7.3 主標題區

```text
桃園市流感及新冠疫苗接種站查詢
更新時間：115/10/01 17:00
```

標題使用思源黑體。若需加強正式感，公告段落可使用思源宋體。

### 7.4 公告提醒區

建議放在查詢條件上方，使用淡藍背景。

```text
接種前請攜帶健保卡及相關證明文件。
實際接種資訊請依里辦公處、轄區衛生所或現場公告為準。
```

公告文字不宜過長。若有多項提醒，使用短句條列。

### 7.5 查詢條件區

桌機版可採 4 欄：

```text
行政區｜里別｜接種日期｜關鍵字
```

手機版採單欄：

```text
行政區
里別
接種日期
關鍵字
[查詢]
[清除條件]
```

關鍵字搜尋範圍：

1. 設站地點名稱。
2. 地址。
3. 承接醫療院所。
4. 備註。

### 7.6 快速篩選

建議提供 chip 樣式快速篩選：

```text
[今天可接種] [本週可接種] [只看流感] [只看新冠]
```

若第一版資料尚無法明確判斷疫苗類型，可先保留「今天可接種」、「本週可接種」。

### 7.7 查詢結果摘要

```text
共找到 28 筆接種站資料
目前篩選：桃園區｜115/10/01
```

若資料量多，結果摘要可固定於查詢條件下方。

### 7.8 接種站卡片規格

每張卡片應以日期時間為最重要資訊。

```text
[桃園區] [南華里]        [今日可接種]

10/1（三） 08:00–12:00
南門市民活動中心
桃園區三民路三段268號

承接院所：敏盛智慧健康管理診所
服務對象：65歲以上長者

流感疫苗：東洋
新冠疫苗：LP.8.1

備註：南華、南門、西湖、西門合辦

[開啟地圖] [複製地址]
```

#### 顯示原則

1. 行政區與里別使用小型標籤。
2. 日期與時間使用較大字級。
3. 地點名稱為卡片主標題。
4. 地址下方提供「開啟地圖」與「複製地址」。
5. 疫苗資訊可用雙欄小資訊塊。
6. 備註過長時預設顯示 2 行，提供「展開」。

### 7.9 民眾端無資料狀態

```text
目前查無符合條件的接種站資料。
請確認行政區、里別或日期，或清除條件重新查詢。
```

按鈕：

```text
[清除條件]
[查看全部場次]
```

### 7.10 民眾端手機版規格

1. 全頁單欄顯示。
2. 查詢條件一欄一列。
3. 接種站資料一律以卡片呈現。
4. 主要按鈕寬度可滿版。
5. 字級不低於 16px。
6. 卡片間距至少 16px。
7. 不使用左右滑動表格。

## 8. GAS 填報端 UI

### 8.1 首頁

首頁採功能卡片，不建議做成傳統文字選單。

```text
桃園市流感及新冠疫苗設站填報系統

主要作業
[回報接種人數]
[新增設站資料]
[維護既有資料]
[查詢場次]

管理作業
[稽催／統計]
[宣導品管理]
[廠商配送回報]
```

#### 首頁排序原則

1. 手機版第一個顯示「回報接種人數」。
2. PC 版可採 2 欄或 3 欄卡片配置。
3. 管理功能需與一般填報功能區隔。
4. 所有子頁均需有「回到首頁」按鈕。

### 8.2 新增設站資料

新增採分步驟 Stepper 表單，避免單頁過長。

```text
第 1 步：選擇行政區與里別
第 2 步：填寫接種日期與時間
第 3 步：填寫設站地點與地址
第 4 步：填寫院所、服務對象與疫苗資訊
第 5 步：填寫宣導品申請
第 6 步：確認資料並送出
```

#### 每一步固定操作

```text
[上一步] [儲存草稿] [下一步]
```

最後一步：

```text
[返回修改] [送出草稿] [送出並發布]
```

### 8.3 第 1 步：行政區與里別

行政區使用下拉選單。

里別使用可搜尋複選清單，不建議自由輸入。

```text
行政區（必填）
[桃園區 v]

里別（必填，可複選）
[搜尋里別]
☑ 南華里
☑ 西湖里
☐ 西門里
```

若選擇多個里別，畫面需提醒：

```text
您已選擇 2 個里別，儲存時將以「、」串接。
```

### 8.4 重複資料提醒

新增時檢查「行政區 + 里別 + 接種日期」。

提示範例：

```text
系統偵測到以下里別於該日期已有設站資料：

南華里：已有 1 筆場次
西湖里：已有 2 筆場次

請確認是否仍要新增。
```

按鈕：

```text
[仍要新增]
[返回修改]
```

### 8.5 第 2 步：日期與時間

```text
接種日期（必填）
[115/10/01]
```

## 15. 表單驗證與錯誤訊息

### 15.1 基本原則

1. 必填欄位需以「必填」文字標示，不只用紅色星號。
2. 錯誤訊息顯示於欄位下方。
3. 錯誤訊息需說明如何修正。
4. 送出後若有多個錯誤，頁面上方需顯示錯誤摘要。
5. 欄位格式提示應在使用者輸入前就顯示。

### 15.2 常見錯誤訊息

| 情境 | 建議訊息 |
|---|---|
| 必填未填 | 請填寫接種日期。 |
| 時間格式錯誤 | 請輸入正確時間格式，例如 0800-1200。 |
| 人數非數字 | 請輸入 0 或正整數。 |
| 接種數超過預估數 | 接種人數已超過預估人數，請確認資料是否正確。 |
| 重複資料 | 此行政區、里別及日期已有設站資料，請確認是否仍要新增。 |
| 管理碼錯誤 | 管理碼錯誤，請確認後重新輸入。 |
| 暫存資料 | 系統偵測到尚未送出的暫存資料，是否恢復？ |

## 18. RWD 響應式規格

### 18.1 斷點

| 裝置 | 寬度 | 設計原則 |
|---|---:|---|
| 手機 | 0–767px | 單欄、卡片、大按鈕 |
| 平板 | 768–1023px | 兩欄或卡片列表 |
| 桌機 | 1024px 以上 | 表格、兩欄表單、完整篩選 |

### 18.2 手機版共同規則

1. 單欄為主。
2. 按鈕高度至少 44px，建議 48px。
3. 不使用大型橫向表格。
4. 表單欄位一列一欄。
5. 卡片間距至少 16px。
6. 重要操作按鈕置於畫面下方或區塊底部。
7. 文字不得小於 14px，一般內文建議 16px。

---

## 19. 無障礙與可用性原則

1. 所有文字與背景需有足夠對比。
2. 不以顏色作為唯一狀態辨識方式。
3. 表單欄位需有明確 label。
4. 錯誤訊息需與欄位對應。
5. 按鈕與連結需可鍵盤操作。
6. 圖示需搭配文字，不單獨使用圖示。
7. 表格需有表頭。
8. Modal 開啟時焦點需停留在 Modal 內。
9. 無資料狀態需提供下一步建議。
10. 民眾端日期、時間、地址需清楚可讀，避免只用縮寫。

## 23. 開發注意事項

1. 民眾端不得直接讀取 Google Sheet 原始資料。
2. 民眾端僅讀取 GAS 產生之公開 JSON。
3. 民眾端不得顯示醫療院所十碼代碼、預估人數、接種人數、接種率、填報人、宣導品配送資訊。

5. 發布後資料需鎖定，避免基本資訊被任意修改。
6. 已配送宣導品之資料不得任意解鎖修改。
7. 回報頁需支援手機操作。
8. 所有重要操作需有成功或失敗提示。
9. 所有送出按鈕需避免重複點擊。
10. 整批上傳需限制單次 100 筆。
