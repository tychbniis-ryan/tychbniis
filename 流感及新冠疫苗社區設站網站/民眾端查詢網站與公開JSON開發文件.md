# 桃園市流感及新冠疫苗接種站民眾端查詢網站與公開 JSON 開發文件

版本：v1.3  
文件用途：提供前端開發者、GAS 開發者及 AI 協作工具建置「民眾端疫苗接種站查詢網站」之依據。  
適用範圍：Firebase Hosting 民眾查詢網站、GAS 產出之 `public.json`、LINE 內建瀏覽器使用情境、QR Code 導流、未來叫號連結與定位導航擴充。
本版重點：納入業務決策，明確定稿第一版功能範圍；定位納入第一版並以 Google Maps 資料為準，正式網址使用 Firebase 預設網址，不導入 LIFF、不啟用匿名流量統計。

---

## 1. 文件目的

本文件用於規劃「桃園市流感及新冠疫苗接種站民眾查詢網站」之前端介面、查詢功能、資料來源與公開 JSON 格式。

本網站主要服務對象為一般民眾，尤其包含高齡者、家屬、照顧者及社區里民。設計重點不在視覺華麗，而在於能快速查詢、容易閱讀、容易操作，並降低民眾在接種前尋找日期、地點、時間及疫苗資訊的負擔。

本文件同時納入 GAS 需產出之公開 JSON 規格，原因為民眾端網站不直接讀取 Google Sheet，而是讀取 GAS 整理後的公開資料檔 `public.json`。

---

## 2. 設計目標

### 2.1 手機容易操作

民眾端以手機使用為主要情境，所有頁面均採手機優先設計。常用功能應可在手機螢幕上單手操作，按鈕高度、文字大小與欄位間距需符合高齡友善原則。

### 2.2 符合情境的快速查詢

網站需提供多種符合民眾實際查詢情境的快捷方式，例如：

- 查詢今日可接種場次。
- 查詢明日場次。
- 查詢本週場次。
- 依行政區查詢。
- 依日期查詢。
- 依地點或地址關鍵字查詢。
- 依疫苗種類或廠牌查詢。
- 依目前位置查詢附近接種站。

### 2.3 保留未來線上叫號查詢擴充

未來若接種站可提供線上叫號、即時排隊或現場候診資訊，本系統需預留欄位，使每筆接種站資料可更新外部超連結。

第一版可先不實作即時叫號功能，但 JSON 與卡片 UI 需預留欄位與按鈕位置。

### 2.4 高齡友善

民眾端需考量長者或視力較弱者使用情境，包含較大的文字、清楚的按鈕、明確的篩選條件、簡單的提示文字與避免過多操作步驟。

### 2.5 語音辨識或語音輔助

語音辨識可列為第二階段或實驗性功能。第一版建議先提供文字搜尋、快捷查詢與定位查詢，語音搜尋作為加值功能，不應成為主要操作方式。

### 2.6 定位遠近與導航

若使用者同意提供定位，網站可依目前位置計算與接種站距離，並提供「由近到遠排序」及「開啟地圖導航」功能。

### 2.7 跨平台與 LINE 使用

本網站定位為「單次查詢使用」之公開查詢網站，民眾不需登入、不需綁定 LINE、不需留下個人資料。

網站需能在手機瀏覽器、LINE 內建瀏覽器、電腦瀏覽器及 QR Code 掃描後正常使用。第一版不導入 LIFF，不綁定 LINE 使用者身分，僅以一般網址分享、LINE 群組轉傳、官方網站連結及 QR Code 導流為主要使用方式。

## 3. 系統架構

```text
Google Sheet 設站資料主表
  ↓
GAS 讀取、整理、篩選公開資料
  ↓
產生 public.json
  ↓
Firebase Hosting 民眾查詢網站
  ↓
民眾以手機或電腦查詢接種站資訊
```

### 3.1 技術分工

| 項目 | 技術 | 說明 |
|---|---|---|
| 資料來源 | Google Sheet | 儲存各接種站設站資料與公開設定 |
| 資料轉換 | Google Apps Script | 篩選公開資料、轉換日期時間、產生 JSON |
| 民眾端網站 | Firebase Hosting | 部署靜態查詢網站 |
| 公開資料 | public.json | 民眾端查詢網站唯一資料來源 |
| 地圖導航 | Google Maps URL 或同等地圖服務 | 開啟外部地圖導航 |
| 定位排序 | Browser Geolocation API + 前端距離計算 | 使用者同意定位後計算附近站點 |

### 3.2 重要原則

1. 民眾端不得直接讀取 Google Sheet 原始資料。
2. 民眾端僅讀取 GAS 產生之 `public.json`。
3. `public.json` 不得包含內部管理欄位。
4. 民眾端僅顯示「是否公開 = 是」且「資料狀態 = 已發布」之資料。
5. 已下架、取消、草稿、未公開資料不得出現在民眾端。
6. 民眾端為單次公開查詢服務，不要求登入、不綁定 LINE、不記錄民眾身分資料。
7. LINE 使用情境以「一般網址在 LINE 內建瀏覽器開啟」為主，第一版不導入 LIFF。
8. 若未來新增線上叫號功能，仍應以每筆資料的公開欄位或外部連結方式提供，不直接公開內部資料表。

## 4. 使用者情境

### 4.1 一般民眾

需求：知道自己附近或指定日期是否有流感／新冠疫苗接種站。  
常見操作：

1. 打開網站。
2. 點選「今日可接種」或選擇行政區。
3. 查看接種地點、日期、時間、地址。
4. 點擊「開啟地圖」前往接種站。

### 4.2 高齡者或家屬協助查詢

需求：快速找到離家近、時間清楚、資訊明確的接種站。  
設計重點：

- 字體需較大。
- 卡片資訊要清楚分層。
- 不要讓使用者填太多欄位。
- 地址、日期、時間要放在卡片最醒目位置。

### 4.3 里辦公處或衛生所協助民眾查詢

需求：快速幫民眾找到特定里別、日期或地點的接種站。  
設計重點：

- 行政區、里別篩選要明顯。
- 關鍵字可搜尋地點、地址、院所與備註。
- 查詢結果可快速複製地址或資訊。

### 4.4 未來接種現場叫號查詢

需求：民眾可從接種站卡片點擊「查看叫號情形」或「現場資訊」。  
設計重點：

- 每筆資料預留叫號連結欄位。
- 若無叫號連結，不顯示按鈕。
- 若有叫號連結，按鈕應清楚標示為外部連結。

### 4.5 LINE 群組或官方網站連結進入

需求：民眾可能從 LINE 群組、里長轉傳訊息、衛生局官網、衛生所公告或 QR Code 進入查詢網站。

設計重點：

- 網站需在 LINE 內建瀏覽器可正常查詢。
- 不要求民眾登入或綁定任何帳號。
- 不要求填寫姓名、電話、身分證字號或 LINE ID。
- 若定位、語音或外部地圖功能在 LINE 內建瀏覽器中無法正常使用，需保留手動查詢方式。
- 每筆接種站資訊應可複製或分享，方便民眾轉傳給家人。

## 5. 網站資訊架構

### 5.1 頁面組成

民眾端第一版建議採單頁式網站，包含以下區塊：

```text
頁首 Header
  ↓
網站標題與更新時間
  ↓
重要提醒公告
  ↓
快捷查詢區
  ↓
進階篩選區
  ↓
查詢結果摘要
  ↓
接種站卡片列表
  ↓
頁尾 Footer
```

### 5.2 頁首 Header

內容建議：

- 桃園市流感及新冠疫苗接種站查詢
- 桃園市政府衛生局
- 最後更新時間

手機版頁首不宜過高，避免壓縮查詢內容。

### 5.3 重要提醒公告

公告內容由 `public.json.notice` 提供。

建議預設文字：

```text
接種資訊依里辦公處、轄區衛生所或現場公告為主，接種前請務必攜帶健保卡及相關證明文件。
```

公告區應置於查詢區上方，但不得過度佔用畫面。

## 6. UI/UX 設計原則

### 6.1 整體風格

設計風格採「公共服務網站」與「醫療資訊查詢」混合方向，需清楚、穩定、可信任，避免過度裝飾。

建議風格：

- 清楚的資訊層級。
- 白底或淡灰底。
- 卡片式查詢結果。
- 穩定的藍色系作為主色。
- 少量輔助色標示狀態。
- 不使用過度漸層、過重陰影或過多裝飾圖示。

### 6.2 字體

建議使用：

```css
font-family: "Noto Sans TC", "Source Han Sans TC", sans-serif;
```

中文名稱：

- 主要介面字體：思源黑體
- 輔助正式說明：思源宋體

使用規則：

| 使用位置 | 建議字體 |
|---|---|
| 網站標題 | 思源黑體 |
| 查詢欄位 | 思源黑體 |
| 按鈕 | 思源黑體 |
| 接種站卡片 | 思源黑體 |
| 公告提醒 | 思源黑體，可搭配思源宋體 |
| 正式說明文字 | 思源宋體或思源黑體 |

### 6.3 字級

| 項目 | 手機版 | 桌機版 |
|---|---:|---:|
| 網站主標題 | 22px | 28px |
| 區塊標題 | 20px | 24px |
| 卡片地點名稱 | 20px | 22px |
| 重要日期時間 | 22px | 24px |
| 一般文字 | 17px | 18px |
| 輔助說明 | 15px | 16px |
| 按鈕文字 | 17px | 18px |

### 6.4 高齡友善操作規格

1. 手機版一般文字不低於 17px。
2. 主要按鈕高度不低於 48px。
3. 按鈕文字需清楚，例如「查詢今日場次」，不要只寫「查詢」。
4. 查詢條件不得一次展開過多欄位。
5. 卡片中最重要的「日期、時間、地點、地址」需優先顯示。
6. 圖示需搭配文字，不單獨使用圖示。
7. 狀態不得只靠顏色辨識，需搭配文字標籤。

## 7. 快捷查詢功能

### 7.1 快捷查詢區

快捷查詢區放在首頁上方，讓民眾不必先理解篩選欄位即可查詢。

建議按鈕：

```text
[今日可接種]
[明日場次]
[本週場次]
[離我最近]
[依行政區查詢]
[依日期查詢]
```

### 7.2 今日可接種

邏輯：

```text
date = 今日日期
且資料狀態 = 已發布
且是否公開 = 是
```

顯示方式：

- 結果依時間由早到晚排序。
- 若有定位資料，可優先顯示距離較近者。
- 若查無資料，顯示「今日查無公開接種站資料，可改查本週場次或其他日期」。

### 7.3 明日場次

邏輯：

```text
date = 明日日期
```

### 7.4 本週場次

邏輯：

```text
date >= 今日
date <= 本週日
```

排序：

```text
日期升冪 → 時間升冪 → 行政區 → 地點名稱
```

### 7.5 依日期查詢

提供日期選擇器，並可搭配行政區查詢。

欄位：

```text
接種日期
行政區（選填）
```

### 7.6 依地點查詢

以關鍵字搜尋：

- 設站地點名稱。
- 地址。
- 行政區。
- 里別。
- 承接醫療院所。
- 備註。

### 7.7 離我最近

需使用使用者定位。若使用者同意定位，系統依目前位置與接種站經緯度計算距離。

若使用者拒絕定位，顯示：

```text
無法取得您的位置。您仍可使用行政區、日期或地點查詢接種站。
```

## 8. 進階篩選功能

### 8.1 篩選條件

第一版建議提供：

| 篩選項目 | 類型 | 說明 |
|---|---|---|
| 行政區 | 下拉選單 | 桃園區、中壢區等 |
| 里別 | 下拉選單或文字搜尋 | 依行政區連動 |
| 接種日期 | 日期選擇器 | 可選單日 |
| 關鍵字 | 文字輸入 | 搜尋地點、地址、院所、備註 |
| 疫苗類型 | 快捷切換 | 流感、新冠、兩者皆有 |
| 服務對象 | 下拉或標籤 | 65歲以上、符合公費等 |

### 8.2 篩選區收合

手機版建議：

- 預設只顯示快捷查詢與關鍵字搜尋。
- 進階條件放在「更多篩選」中。
- 篩選完成後顯示目前條件摘要。

範例：

```text
目前條件：桃園區｜10/1｜流感疫苗
[清除條件]
```

### 8.3 清除條件

每次查詢後應提供「清除條件」按鈕，避免民眾不知道目前被哪些條件限制。

## 9. 查詢結果卡片 UI

### 9.1 卡片資訊層級

每筆接種站資料以卡片呈現，優先順序如下：

1. 日期與時間。
2. 設站地點名稱。
3. 行政區與里別。
4. 地址。
5. 疫苗資訊。
6. 服務對象。
7. 承接醫療院所。
8. 備註。
9. 地圖導航與未來叫號連結。

### 9.2 卡片範例

```text
[桃園區] [南華里] [今日可接種]

10/1（三） 08:00–12:00
南門市民活動中心
桃園區三民路三段268號

流感疫苗：東洋
新冠疫苗：LP.8.1
服務對象：65歲以上長者
承接院所：敏盛智慧健康管理診所

備註：南華、南門、西湖、西門合辦

[開啟地圖] [複製地址] [查看叫號]
```

### 9.3 今日場次標籤

若 `date` 為今日，卡片顯示：

```text
今日可接種
```

若時間已過，可顯示：

```text
今日已結束
```

但是否隱藏已結束場次需由業務單位決定。

### 9.4 疫苗資訊顯示

若該場次有提供流感疫苗：

```text
流感疫苗：東洋
```

若該場次有提供新冠疫苗：

```text
新冠疫苗：LP.8.1
```

若欄位空白，不建議顯示「無」，避免民眾誤解，可改為不顯示該疫苗列，或顯示「請洽現場確認」。此項需由業務單位決定。

### 9.5 地址與導航

每張卡片提供：

- 開啟地圖。
- 複製地址。
- 若有經緯度，可顯示距離。

範例：

```text
距離您約 1.2 公里
[開啟導航]
```

## 10. 定位、距離排序與導航

### 10.1 定位功能

第一版納入定位遠近查詢功能。定位功能需經使用者同意後才可取得位置，網站應於使用者點選「查附近接種站」時才要求定位，不應進入網站即要求定位。

定位僅用於使用者當次查詢與前端距離排序，不寫回 Google Sheet，不儲存民眾定位資料，也不作為後續追蹤用途。

### 10.2 距離計算條件

第一版距離排序以 Google Maps 可查得之地點資料為準。若接種站能維護經緯度，`public.json` 每筆資料建議提供：

```json
"lat": 24.993628,
"lng": 121.301337
```

若無經緯度，該筆資料仍可顯示地址與「開啟地圖」按鈕，但不納入精準距離排序；前端可將無座標資料排於有座標資料之後，並不顯示距離。

### 10.3 距離排序邏輯

1. 使用者點擊「查附近接種站」。
2. 瀏覽器請求定位權限。
3. 使用者同意後取得目前經緯度。
4. 前端以 Haversine 公式或等效方式計算距離。
5. 查詢結果依距離由近到遠排序。
6. 已結束場次仍排序於後方，避免距離最近但已無法接種的場次干擾民眾判斷。

### 10.4 無法定位時

顯示友善提示：

```text
無法取得您的位置，可能是尚未授權定位或瀏覽器不支援。您仍可使用行政區、日期或地點查詢接種站。
```

### 10.5 導航功能

第一版建議使用外部地圖連結，不必自行開發地圖。

按鈕名稱建議：

```text
開啟地圖
```

若未來要更明確：

```text
開啟 Google 地圖導航
```

## 11. 語音辨識或語音輔助

### 11.1 可行性評估

語音搜尋可行，但不建議列為第一版核心功能。原因：

1. 各瀏覽器支援程度可能不同。
2. 中文地名、里名、活動中心名稱可能辨識錯誤。
3. 高齡者使用時，若辨識錯誤，反而增加操作挫折。
4. 公共服務網站仍需保留文字輸入與按鈕查詢作為主要操作方式。

### 11.2 建議定位

第一版：不做語音辨識，先完成快捷查詢、文字搜尋、定位與導航。  
第二版：可加入「語音搜尋」按鈕作為輔助功能。

### 11.3 語音搜尋 UI

若第二版開發，建議放在關鍵字搜尋欄旁：

```text
搜尋地點、地址或里別  [麥克風]
```

使用者點擊後顯示：

```text
請說出行政區、地點或日期，例如：桃園區今日接種站。
```

辨識完成後，不要直接送出，應先填入搜尋欄讓使用者確認。

### 11.4 語音搜尋錯誤提示

```text
沒有辨識到清楚的內容，請再說一次，或直接輸入地點、日期、行政區查詢。
```

## 13. 跨平台、LINE 與 QR Code 使用情境

### 13.1 設計定位

本網站為公開查詢網站，定位為「民眾單次查詢使用」。民眾只需打開網址、選擇條件、查看接種站資訊，不需建立帳號、不需登入、不需綁定 LINE，也不需留下個人資料。

第一版不導入 LIFF，不以 LINE 使用者身分、好友狀態或官方帳號綁定作為功能前提。LINE 僅作為連結傳遞與開啟網站的入口。

### 13.2 主要入口

網站需支援下列入口：

1. 衛生局或市府官網連結。
2. LINE 群組轉傳連結。
3. LINE 官方帳號圖文選單或推播連結。
4. 衛生所、里辦公處或接種站公告 QR Code。
5. 宣導單張、海報或新聞稿 QR Code。
6. 民眾自行將網址加入手機瀏覽器書籤。

### 13.3 LINE 內建瀏覽器使用原則

民眾從 LINE 點擊連結時，可能會在 LINE 內建瀏覽器開啟。網站需確保基本查詢功能在 LINE 內建瀏覽器中可使用。

應注意：

1. 不依賴登入、Cookie 或跨頁複雜狀態。
2. 不以彈出視窗作為主要操作方式。
3. 查詢條件需以按鈕、下拉選單與文字搜尋為主。
4. 定位功能若失敗，需顯示手動查詢替代方式。
5. 外部地圖導航需使用一般連結開啟，不強制嵌入地圖。
6. 頁面上可提供「在瀏覽器開啟」提示文字，供定位或地圖功能異常時使用。

### 13.4 不導入 LIFF 的理由與規格影響

第一版不建議導入 LIFF，理由如下：

1. 本網站為單次查詢服務，沒有會員、預約、個人化通知或綁定資料需求。
2. 民眾端只需要查詢公開接種站資訊，不需要取得 LINE 使用者資料。
3. 一般 RWD 網站即可滿足 LINE、官網、QR Code 與手機瀏覽器使用情境。
4. 不導入 LIFF 可降低開發與維護成本，也避免未來平台規格調整造成額外維護。

因此第一版應採「一般公開網址 + RWD 手機版 + LINE 內建瀏覽器相容」方式開發。

### 13.5 LINE 分享與複製資訊

每筆接種站卡片建議提供「分享此場次」或「複製資訊」功能，方便民眾將資訊轉傳給家人、長者或里民。

第一版建議優先提供「複製資訊」功能，避免不同瀏覽器分享支援不一致。若瀏覽器支援 Web Share API，可加上「分享」按鈕。

分享文字範例：

```text
桃園市流感及新冠疫苗接種站資訊
行政區／里別：桃園區 南華里
日期時間：115/10/1 08:00-12:00
地點：南門市民活動中心
地址：桃園區三民路三段268號
服務對象：65歲以上長者
查詢連結：https://example.gov.tw/vaccine?siteId=SITE-20251001-0001
```

### 13.6 QR Code 使用原則

若網站連結印製於宣導單張、海報、通知單或里辦公處公告，需考量 QR Code 掃描後的第一個畫面。

QR Code 預設可導向民眾端首頁，並提供：

1. 今日可接種。
2. 依行政區查詢。
3. 依日期查詢。
4. 搜尋地點或地址。
5. 使用我的位置查附近接種站。

若需要針對特定行政區、特定日期或特定場次製作 QR Code，網站需支援網址參數。

### 13.7 建議網址參數

為支援 LINE、QR Code、官網導流及未來宣導素材，民眾端網址建議支援 query string。

| 參數 | 用途 | 範例 |
|---|---|---|
| district | 預設行政區 | `?district=桃園區` |
| village | 預設里別 | `?village=南華里` |
| date | 預設日期 | `?date=2025-10-01` |
| keyword | 預設關鍵字 | `?keyword=南門` |
| siteId | 開啟特定場次 | `?siteId=SITE-20251001-0001` |
| source | 來源追蹤 | `?source=line`、`?source=qrcode`、`?source=official` |

來源追蹤僅建議用於簡易流量分析，不應記錄個人身分。

### 13.8 隱私與個資原則

民眾端網站第一版不得要求民眾提供下列資料：

1. 姓名。
2. 電話。
3. 身分證字號。
4. 生日。
5. LINE ID。
6. 健保卡號。
7. 個人接種紀錄。

定位功能如有使用，僅於使用者同意後在前端進行距離計算。第一版不建議將民眾定位資料寫回後端或 Google Sheet。

### 13.9 第一版建議做法

第一版納入：

1. 一般 RWD 公開網站。
2. LINE 內建瀏覽器可正常查詢。
3. QR Code 掃描後可直接查詢。
4. 支援網址參數。
5. 複製地址。
6. 複製場次資訊。
7. 開啟外部地圖導航。
8. 不登入、不綁定、不留個資。

第一版不納入：

1. LIFF。
2. LINE 登入。
3. LINE 使用者綁定。
4. 個人化通知。
5. 個人接種紀錄查詢。
6. 需登入才能使用的收藏或提醒功能。

## 14. 公開 JSON 產出規格

### 14.1 JSON 產生來源

`public.json` 由 GAS 讀取 Google Sheet 主資料表與公開設定表後產生。

### 14.2 JSON 產生時機

建議：

1. 每次資料新增、修改、發布、下架後自動重新產生。
2. 另以 GAS 觸發器每 5 至 10 分鐘定時產生一次。
3. 每次產生需寫入 JSON 輸出紀錄。

### 14.3 JSON 篩選條件

僅輸出：

```text
是否公開 = 是
資料狀態 = 已發布
```

不輸出：

```text
草稿
下架
取消
未公開
```

### 14.4 JSON 不得包含欄位

`public.json` 不得包含：

- 醫療院所十碼代碼。
- 流感疫苗預估人數。
- 流感疫苗接種人數。
- 流感疫苗接種率。
- 新冠疫苗預估人數。
- 新冠疫苗接種人數。
- 新冠疫苗接種率。
- 填報單位。
- 填報人。
- 填報人 Email。
- 是否公開。
- 資料狀態。
- 異動紀錄。
- 宣導品配送資料。
- 內部管理碼或權限資料。

## 15. 前端查詢邏輯

### 15.1 初始化

1. 載入 `public.json`。
2. 檢查 `isOpen`。
3. 顯示標題、公告與更新時間。
4. 若 `defaultView = today`，預設顯示今日場次。
5. 若今日無資料，顯示本週快捷查詢提示。

### 15.2 排序規則

一般查詢預設排序：

```text
日期升冪 → 開始時間升冪 → 行政區 → 地點名稱
```

定位查詢排序：

```text
距離升冪 → 日期升冪 → 開始時間升冪
```

### 15.3 關鍵字搜尋

搜尋範圍：

```text
district
village
siteName
address
hospitalName
target
fluBrand
covidBrand
note
```

建議忽略空白與全形半形差異。

### 15.4 日期判斷

日期比較一律使用 `date` 欄位，不使用 `rocDate`。

### 15.5 今日已結束判斷

若要顯示「今日已結束」，需使用 `date`、`endTime` 與使用者目前時間比對。

## 17. RWD 響應式規格

### 17.1 手機版

螢幕寬度小於 768px：

- 單欄版面。
- 快捷查詢按鈕採 2 欄或橫向滑動。
- 查詢結果以卡片呈現。
- 進階篩選預設收合。
- 主要按鈕高度至少 48px。

### 17.2 平板版

螢幕寬度 768px 至 1023px：

- 查詢條件可採 2 欄。
- 卡片可維持單欄或 2 欄，視資訊密度調整。

### 17.3 桌機版

螢幕寬度 1024px 以上：

- 查詢區可採多欄排列。
- 結果卡片可採 2 欄。
- 不建議改為純表格，因民眾端仍以閱讀清楚為優先。

## 18. 無障礙與高齡友善要求

1. 文字與背景需有足夠對比。
2. 所有輸入欄位需有明確 label。
3. 不以顏色作為唯一資訊判斷。
4. 按鈕需有明確文字。
5. 表單錯誤或查無資料需提供下一步操作。
6. 支援鍵盤操作。
7. 外部連結需標示清楚。
8. 螢幕閱讀器可讀取主要內容。
9. 不自動播放聲音或動畫。
10. 重要資訊不得只放在圖片中。

1. LIFF。
2. LINE 帳號綁定。
3. 特定行政區 QR Code 或特定場次 QR Code。
4. 匿名流量統計。
5. 語音搜尋。
6. 地圖檢視模式。

LINE 使用以「複製或轉傳 LINE 文字」為主，不建立 LINE 使用者識別、不綁定個人資料。

### 19.4 第二版再評估功能

1. 語音搜尋。
2. 地圖檢視模式。
3. 多語或簡易語言版本。
4. 與叫號系統進行即時狀態串接。
5. Apple 地圖或其他地圖服務優化。
6. 常用行政區或使用偏好記憶功能。

## 20. UX 驗收標準

本章作為民眾端查詢網站之驗收依據，避免僅完成技術功能，但實際使用上不夠直覺或不符合高齡友善。

### 20.1 手機操作驗收

1. 使用手機開啟網站後，第一屏需看得到網站名稱、更新時間及至少 3 個快捷查詢入口。
2. 使用者不需左右滑動畫面，即可閱讀接種站主要資訊。
3. 主要按鈕高度不得低於 48px。
4. 一般文字不得低於 17px。
5. 點擊「今日可接種」後，需在同頁顯示查詢結果，不應跳轉至複雜頁面。
6. 查詢結果卡片需直接顯示日期、時間、接種地點、地址，不得隱藏於展開區。
7. 第一屏不應一次顯示過多篩選欄位；進階篩選應收合。

### 20.2 高齡友善驗收

1. 所有主要按鈕需使用完整文字，例如「查詢今日場次」、「開啟地圖」，不得僅使用圖示。
2. 查無資料時需提供下一步操作，例如「查看本週場次」、「清除條件」、「改查行政區」。
3. 定位失敗時需提供手動查詢替代方案。
4. 重要資訊不得只以顏色表示，需搭配文字標籤。
5. 接種日期與時間需比一般內文明顯，建議字級不低於 22px。
6. 不得使用過小、過淡、低對比文字作為主要資訊。
7. 卡片內欄位名稱需口語化，例如「接種地點」、「服務院所」、「服務對象」。

### 20.3 LINE 與 QR Code 使用驗收

1. 從 LINE 點擊連結後，可正常開啟網站。
2. LINE 內建瀏覽器中可使用今日、本週、行政區、日期與關鍵字查詢。
3. 若定位無法使用，需顯示替代查詢方式。
4. 每筆卡片至少提供「複製地址」或「複製資訊」功能。
5. 外部地圖連結需可正常開啟。
6. 網站不得要求登入、不得綁定 LINE、不得要求民眾提供個資。
7. QR Code 掃描後需可直接進入對應首頁、行政區或場次頁面。

### 20.4 查詢體驗驗收

1. 今日查詢結果需依時間排序。
2. 今日已結束場次需標示「今日已結束」並排序在後方。
3. 行政區查詢後，結果摘要需顯示目前條件及筆數。
4. 清除條件後需回復預設查詢狀態。
5. `siteId` 網址參數可直接開啟特定場次。
6. `district`、`date`、`keyword` 網址參數可正確帶入查詢條件。
7. 若查無資料，畫面不得只顯示「查無資料」，需提供下一步。

### 20.5 資料顯示驗收

1. 民眾端不得顯示醫療院所十碼代碼、預估人數、接種人數、接種率、填報人、內部狀態及宣導品配送資料。
2. `public.json` 更新時間需顯示於頁面明顯位置。
3. `queueUrl` 空白時不得顯示叫號按鈕。
4. `queueUrl` 有值時，需以外部連結方式開啟。
5. `mapUrl` 空白時，前端需可用地址產生地圖搜尋連結。
6. 疫苗廠牌空白時，不得顯示「未填報」。

## 21. 業務決策紀錄與第一版定稿事項

以下事項已依業務決策定稿，開發者應依本章辦理，後續不再列為待確認事項。

### 21.1 定位遠近

第一版納入「查附近接種站」與距離排序功能。

執行原則：

1. 距離與地點資料依 Google Maps 資料為準。
2. 若接種站資料有 `lat`、`lng`，前端可依使用者目前位置計算距離並由近到遠排序。
3. 若接種站資料無 `lat`、`lng`，仍顯示該場次資料與「開啟地圖」按鈕，但不顯示距離。
4. 定位僅供當次查詢與前端排序，不儲存、不寫回、不追蹤民眾定位資料。
5. 定位失敗或使用者拒絕授權時，需提供行政區、日期、地點關鍵字等替代查詢方式。

### 21.2 正式網址

第一版使用 Firebase 預設網址，不另申請機關正式子網域。

執行原則：

1. Firebase Hosting 預設網址作為第一版民眾端正式使用網址。
2. 網頁標題、頁首與頁尾需清楚標示「桃園市流感及新冠疫苗接種站查詢」及主管機關資訊，以增加民眾辨識度。
3. 若未來需正式機關子網域，可於第二階段再處理，不影響第一版開發。

### 21.3 叫號連結欄位

第一版即納入叫號相關欄位，但不強制每筆填寫。

欄位如下：

```tsv
queueUrl	queueLabel	queueUpdatedAt
```

執行原則：

1. `queueUrl` 有值時，民眾端卡片顯示叫號或現場資訊按鈕。
2. `queueUrl` 空白時，不顯示叫號按鈕。
3. `queueLabel` 可作為按鈕文字，例如「查看叫號情形」、「查看現場資訊」。
4. `queueUpdatedAt` 可顯示叫號資訊最後更新時間。
5. 叫號資訊屬外部連結，畫面需保留「實際接種情形依現場公告為準」之提醒。

### 21.4 服務對象用語

第一版不強制統一服務對象固定選項。

執行原則：

1. 民眾端依 Google Sheet 或 JSON 內 `target` 欄位原文顯示。
2. 前端不需限制服務對象為固定選項。
3. 若內容過長，卡片可顯示前兩行並提供展開。
4. 後續若業務上需要標準化，可於第二階段再調整填報端選項。

### 21.5 LINE 與 QR Code 導流方式

第一版不製作特定行政區 QR Code 或特定場次 QR Code，不導入 LIFF，不綁定 LINE。

執行原則：

1. LINE 使用以一般網址開啟與文字轉傳為主。
2. 每筆場次提供「複製場次資訊」功能，方便貼到 LINE。
3. 不需要 LINE 登入、不綁定使用者、不取得 LINE 個人資料。
4. 可保留一般網址參數支援，供未來宣導或官網連結使用，但第一版不大量製作特定 QR Code。

建議 LINE 轉傳文字格式：

```text
桃園市流感及新冠疫苗接種站資訊
行政區／里別：{district} {village}
日期時間：{rocDate} {time}
接種地點：{siteName}
地址：{address}
服務對象：{target}
查詢連結：{url}
提醒：接種資訊依里辦公處、轄區衛生所或現場公告為準，請攜帶健保卡及相關證明文件。
```

### 21.6 匿名流量統計

第一版不啟用匿名流量統計。

執行原則：

1. 不導入網站流量統計工具。
2. 不記錄民眾個資。
3. 不記錄民眾定位資料。
4. 不紀錄民眾查詢條件作為使用者追蹤。

若未來需統計使用量，應另行評估資訊安全、隱私告知與統計資料最小化原則。

### 21.7 地圖服務使用方式

第一版固定使用 Google Maps URL。

執行原則：

1. 卡片按鈕文字固定為「開啟地圖」。
2. 不自行開發嵌入式地圖。
3. 不另做 Apple 地圖或其他地圖服務切換。
4. 若 `mapUrl` 有值，使用 `mapUrl`。
5. 若 `mapUrl` 空白，前端可依地址組成 Google Maps 搜尋連結。

## 22. 主要風險與配套方案

| 風險 | 可能情境 | 影響 | 配套方案 |
|---|---|---|---|
| 首頁資訊太多 | 民眾看到很多欄位不知道怎麼查 | 使用率低、電話詢問增加 | 第一屏只放 4 個快捷入口，進階條件收合 |
| 高齡者不會輸入關鍵字 | 不知道要輸入里名、地址或地點 | 查不到資料 | 以按鈕與下拉為主，文字搜尋為輔 |
| LINE 內建瀏覽器功能不穩 | 定位、分享、地圖開啟異常 | 民眾誤認網站壞掉 | 基本查詢不依賴定位；提供複製地址與手動查詢 |
| 定位權限被拒絕 | 使用者按「查附近接種站」但拒絕定位 | 無法排序遠近 | 顯示替代操作，不中斷流程 |
| 經緯度資料不完整 | 部分地址沒有 `lat`、`lng` | 距離排序不準 | 只對有座標資料排序；無座標資料仍可查詢與開啟地圖 |
| 叫號連結失效 | 外部系統維護或網址填錯 | 民眾不信任資訊 | `queueUrl` 需格式檢核，連結旁加「以現場為準」 |
| 疫苗廠牌空白 | 前端顯示不當文字 | 民眾不安或誤解 | 不顯示「未填報」；改顯示「請洽現場確認」或隱藏 |
| 已結束場次消失 | 下午查不到上午資料 | 民眾以為資料錯誤 | 今日已結束仍顯示，排序在後 |
| JSON 更新延遲 | GAS 尚未更新 `public.json` | 前台與 Sheet 不一致 | 顯示最後更新時間；保留 JSON 輸出紀錄 |
| 外部地圖導錯位置 | 地址格式不完整或地圖判讀錯誤 | 民眾跑錯地點 | 上線前抽測地址；必要時維護 `mapUrl` 或 `lat/lng` |
| 資料量變大後載入慢 | 全市資料多、手機網路慢 | 首頁卡頓 | JSON 壓縮；前端先顯示符合條件前 50 筆 |
| 無資料提示不清楚 | 只顯示「查無資料」 | 使用者不知道下一步 | 提供「查看本週」、「清除條件」、「改查行政區」 |

## 23. 上線前使用情境測試

建議上線前進行小規模使用測試，測試對象包含：

1. 一般民眾。
2. 55 歲以上使用者。
3. 衛生所或里辦公處協助查詢人員。
4. 不熟悉系統但常用 LINE 的使用者。

### 23.1 測試任務

1. 從 LINE 點擊連結，查詢今日可接種場次。
2. 查詢某一行政區的本週場次。
3. 找到指定地點，並開啟地圖。
4. 將某一場次資訊複製後貼到 LINE。
5. 在查無資料時，改查其他日期或行政區。

### 23.2 驗收指標

1. 多數使用者可在 30 秒內找到今日或本週場次。
2. 使用者不需教學即可理解「今日可接種」、「依行政區查詢」、「開啟地圖」功能。
3. 使用者知道查無資料後下一步可以做什麼。
4. 使用者可成功複製資訊並貼到 LINE。
5. 使用者不會誤以為需要登入或綁定 LINE。
