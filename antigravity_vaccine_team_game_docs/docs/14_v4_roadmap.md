# 14 第 4 版開發路線圖

## 版本定位

第 4 版以 `0.4.0-planning` 啟動。目標不是重寫第 3 版，而是把已定版的現場遊戲系統整理成更適合公務機關活動使用的維運版。

第 4 版預設延續第 3 版免費方案：

1. Firebase Hosting：學員端與講師端入口。
2. Firebase Realtime Database：公開狀態、公開題庫、暫時排行榜與高頻暫存資料。
3. GAS / Google Sheets：正式資料、管理操作、計分、結算與報表。
4. Cloud Functions、Cloud Run、Blaze：未啟用，除非使用者另行明確確認。

## 第 4 版核心目標

1. 降低正式活動前設定錯誤風險。
2. 提供可直接執行的活動前檢查流程。
3. 強化資料備份、賽後匯出與交接文件。
4. 保留第 3 版遊戲功能，不大改現場操作流程。
5. 讓非工程人員能依文件完成檢查、啟動、還原與交接。

## P0：活動前健康檢查

### 問題

第 3 版功能已完整，但正式活動前仍需人工確認 GAS Script Properties、題庫、戰隊設定、Firebase Hosting、Realtime Database 與管理密碼。若現場才發現設定缺漏，會直接影響報到、開題或計分。

### 解法

規劃新增一個保守的健康檢查流程，先以文件與檢查清單開始，後續再評估是否做成講師端按鈕。

檢查項目：

1. GAS Web App 是否可呼叫 `getGameState`。
2. Firebase Hosting 學員端是否回應 `200`。
3. Firebase Hosting 講師端是否回應 `200`。
4. `GAME_ID` 是否存在。
5. `ADMIN_API_SECRET` 是否存在但不顯示內容。
6. 題庫是否至少有 1 題啟用。
7. 戰隊設定是否有 5 個啟用戰隊。
8. Realtime Database 公開狀態是否可讀。
9. 測試資料是否已初始化。

### 驗收標準

1. 檢查結果使用「通過 / 需處理」呈現。
2. 不輸出管理密碼、Token、Cookie、private key 或個資。
3. 檢查失敗時以 Status、Root Cause、Suggested Fix 顯示。

## P1：正式活動操作手冊

### 問題

目前文件偏向工程交接，承辦人正式活動當天需要更短、更直接的操作流程。

### 解法

新增活動操作手冊，分成活動前、活動中、活動後。

活動前：

1. 開啟講師端。
2. 輸入管理密碼並套用設定。
3. 初始化遊戲資料。
4. 啟動場次。
5. 確認學員端可報到。

活動中：

1. 開題。
2. 請學員翻開試卷。
3. 關題關閉。
4. 確認答案與排行榜。
5. 下一題重複操作。

活動後：

1. 結算競賽。
2. 匯出報表。
3. 保存 Google Sheets。
4. 保存 Git 版本與部署紀錄。

### 驗收標準

1. 文件可由非工程人員照步驟操作。
2. 每個高風險動作都寫明影響範圍與還原方式。
3. 不要求使用者理解程式碼。

## P2：賽後資料保存與交接

### 問題

活動後需要保留成績、作答紀錄、獎項與部署版本。若只靠人工截圖或臨時下載，後續查核與交接會不穩定。

### 解法

整理賽後保存流程，後續再評估是否補自動化。

保存項目：

1. 賽後報表試算表連結。
2. 活動日期與 `GAME_ID`。
3. 學員端與講師端 Hosting URL。
4. GAS Web App deployment version。
5. Git commit。
6. 第 4 版操作紀錄。

### 驗收標準

1. 不保存完整姓名、身分證字號、帳密或 Token。
2. 報表交接資訊集中在文件中。
3. 後續 AI 可依文件找到活動版本與還原點。

## P3：講師端低風險輔助功能

### 問題

講師端已具備主要功能，但正式活動時需要更清楚的狀態提示，避免誤按初始化、重複開題或未結算就結束活動。

### 解法

保守規劃下列 UI 輔助，不在 `0.4.0-planning` 直接實作：

1. 活動前檢查狀態區。
2. 初始化前二次確認。
3. 開題前顯示題號與題型確認。
4. 結算前確認尚未完成事項。
5. 賽後報表匯出完成提示。

### 驗收標準

1. UI 只呼叫既有模組或新增後端 API。
2. 不把 GAS、Excel、Firebase 操作邏輯寫進 UI。
3. 不顯示敏感設定內容。

## 第 4 版建議開發順序

1. `0.4.0-planning`：建立第 4 版路線圖、版本標記與交接紀錄。
2. `0.4.1`：新增正式活動操作手冊。
3. `0.4.2`：新增本機或 GAS 健康檢查規格。
4. `0.4.3`：補講師端活動前檢查入口。
5. `0.4.4`：整理賽後資料保存與交接流程。
6. `0.4.5`：依實測結果修正現場操作細節。

## 第 4 版不做事項

1. 不重寫第 3 版已定版功能。
2. 不啟用付費服務。
3. 不新增需要管理員權限或複雜伺服器的依賴。
4. 不把管理密碼、Token、Cookie、private key 或個資寫入程式或文件。
5. 不在未經確認時部署 GAS、Firebase Hosting、Firebase rules 或 Cloud Functions。

## 0.4.0-planning 完成範圍

Status：第 4 版規格啟動。

Root Cause：第 3 版已於 `0.3.22` 定版，後續需求應從現場維運、活動前檢查、資料保存與交接流程開始，避免直接改動已可用的遊戲主流程。

Suggested Fix：先建立第 4 版路線圖與版本標記，後續每次只挑選一個小功能實作，先本機測試，再由使用者決定是否部署。

本次不修改：

1. 學員端正式功能。
2. 講師端正式功能。
3. GAS `Code.gs`。
4. Firebase rules。
5. Firebase Hosting 部署內容。
