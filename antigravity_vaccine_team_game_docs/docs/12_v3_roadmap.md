# 12 第 3 版製作路線圖

## 版本定位

第 3 版目標是把 `docs/01_game_rules.md` 的完整遊戲規則，拆成可維護、可測試、可逐步上線的功能版本。

第 3 版不改變第 2 版已定版架構：

1. Firebase Hosting：學員端與講師端入口。
2. Firebase Realtime Database：只放公開狀態、公開題庫與公開排行榜。
3. GAS / Google Sheets：正式資料來源、規則判斷、計分、抽獎與報表。
4. Cloud Functions：免費方案暫停，不納入第 3 版必要條件。

## 第 3 版核心原則

1. 先補資料結構，再補 API，再補 UI。
2. 抽寶箱、道具、幸運獎、全對獎與票選判定都必須在 GAS 執行。
3. 學員端不得取得正確答案、未公開分數細節、抽獎亂數種子或管理設定。
4. 每次只上線一個子功能，避免活動現場一次承受多個新風險。
5. 第 2 版核心流程可獨立運作；第 3 版功能失效時，仍可退回第 2 版問答與排行榜。

## 規則來源

第 3 版以 `docs/01_game_rules.md` 為唯一規則來源。已納入的規則如下：

1. 5 個戰隊。
2. 約 200 名學員。
3. 戰隊勝利條件為戰隊加權平均分。
4. 個人答題分數依答對時間給分。
5. 每題最快答對者加 5 分。
6. 每人最多持有 3 個寶箱。
7. 幸運獎全場 1 名。
8. 全對獎 3 名，依完成時間排序。
9. 寶箱可抽到加分卡、加倍卡、翻身卡、挑戰卡、特殊道具或空寶箱。
10. 創作票選題分為隊內初選、講師選代表、匿名全體投票。

## P0：第 3 版基礎資料結構

### 問題

目前第 2 版已能完成問答、計分與排行榜，但缺少寶箱、道具、獎項與票選資料表。若直接改 UI，資料會無法追蹤，也不利於活動後查核。

### 解法

新增或規劃下列 Google Sheets 工作表：

| 工作表 | 用途 | 是否含敏感資料 |
|---|---|---|
| 寶箱紀錄 | 記錄寶箱取得、開啟、失效與來源 | 否 |
| 道具紀錄 | 記錄抽到的道具、使用時機與結果 | 否 |
| 獎項紀錄 | 記錄幸運獎與全對獎得主 | 否 |
| 創作投稿 | 記錄創作票選題投稿內容 | 可能含自由文字 |
| 創作投票 | 記錄隊內初選與全體投票 | 否 |
| 規則設定 | 保存寶箱機率、持有上限、投票秒數 | 否 |

### 驗收標準

1. `setupGameSheets` 可建立第 3 版工作表。
2. `resetGameData` 可清除第 3 版活動紀錄，但保留規則設定。
3. 所有第 3 版工作表欄位寫入 `gas/README.md`。
4. 不記錄完整姓名、身分證字號、帳密或 Token。

## P1：寶箱取得與持有限制

### 問題

規則要求多種寶箱取得條件，且每人最多持有 3 個。這必須由後端統一判斷，避免學員端自行計算造成作弊或不同步。

### 解法

GAS 在關題計分後判斷寶箱取得：

1. 每題答對有 30% 機率取得 1 個寶箱。
2. 正確回答 3 題取得 1 個寶箱。
3. 正確回答 5 題取得 1 個寶箱。
4. 正確回答 10 題取得 2 個寶箱。
5. 連續答對 3 題取得 1 個寶箱。
6. 連續答對 5 題取得 2 個寶箱。
7. 使用道具 3 次取得 1 個寶箱。
8. 使用道具 5 次取得 1 個寶箱。

持有限制：

1. 每人最多 3 個未開啟寶箱。
2. 超過 3 個時，系統自動丟棄最早取得且尚未開啟的寶箱。
3. 活動結束時，未使用寶箱標記為失效。

### API 規劃

| action | 使用者 | 說明 |
|---|---|---|
| getPlayerInventory | 學員 | 讀取自己的未開啟寶箱與可用道具 |
| openTreasureBox | 學員 | 開啟自己的寶箱 |
| expireUnusedBoxes | 講師 | 活動結束後讓未開啟寶箱失效 |

### 驗收標準

1. 同一題重複關題不會重複發寶箱。
2. 同一學員重新整理頁面後，寶箱狀態不重複產生。
3. 未開啟寶箱最多保留 3 個。

## P2：道具效果與戰隊加成

### 問題

第 2 版排行榜主要依答題分數排序。第 3 版規則要求戰隊加權平均分與道具加成，必須明確拆分「個人答題分」、「戰隊道具加成」與「最終排名分」。

### 解法

戰隊最終分數採下列公式：

```text
戰隊加權平均分 = 戰隊總得分 / 有效參與人數 + 戰隊任務加成
```

其中：

1. 戰隊總得分：所有有效學員的個人答題分加總。
2. 有效參與人數：至少完成 1 題作答的學員。
3. 戰隊任務加成：加分卡、翻身卡、挑戰卡等道具產生的隊伍加成。

道具規則：

| 道具 | 後端判定方式 |
|---|---|
| 小加分卡 | 題後使用，戰隊 +1，每題限用 1 張 |
| 中加分卡 | 題後使用，戰隊 +3，每題限用 1 張 |
| 大加分卡 | 題後使用，戰隊 +5，每題限用 1 張 |
| 超級加分卡 | 題後使用，戰隊 +10，每題限用 1 張 |
| 加倍卡 | 題前使用，下一題答對時個人分數 x2，額外加成上限 20 分 |
| 翻身卡 | 題後使用，本隊最後一名 +30，否則 +5，每隊最多觸發 2 次 |
| 挑戰卡 | 題前指定一隊，下一題本隊答對率較高 +10，否則 +3 |
| 特殊道具 | 取得即成為幸運獎，且全場只產生 1 名 |

### API 規劃

| action | 使用者 | 說明 |
|---|---|---|
| useItem | 學員 | 使用指定道具 |
| getTeamBonusLedger | 講師 | 讀取戰隊道具加成明細 |
| recalculateV3Scoreboard | 講師 | 重新計算第 3 版排行榜 |

### 驗收標準

1. 個人答題分與戰隊道具加成分開保存。
2. 加倍卡不提前揭露下一題答案。
3. 挑戰卡不扣對方分數。
4. 翻身卡每隊最多觸發 2 次。
5. 幸運獎產生後，特殊道具不再進入抽獎結果。

## P3：全對獎與幸運獎

### 問題

全對獎與幸運獎都會影響頒獎結果。若只靠現場人工判斷，活動後難以追溯。

### 解法

由 GAS 在活動結束或講師手動結算時產生獎項紀錄：

1. 全對獎：
   - 全部正式題目皆答對。
   - 依完成最後一題的送出時間排序。
   - 取前 3 名。
2. 幸運獎：
   - 第一位抽中特殊道具者取得。
   - 幸運獎產生後，特殊道具獎池關閉。
   - 若完成總題數 70% 後仍未產生，特殊道具機率由 3% 提高為 10%，直到產生為止。

### API 規劃

| action | 使用者 | 說明 |
|---|---|---|
| finalizeAwards | 講師 | 結算幸運獎與全對獎 |
| getAwardList | 講師 | 讀取頒獎名單 |

### 驗收標準

1. 全對獎最多 3 名。
2. 幸運獎最多 1 名。
3. 重新結算不會重複產生不同得主，除非講師先執行初始化。

## P4：創作票選題

### 問題

創作題包含自由文字、隊內初選、講師選代表與匿名全體投票。這是第 3 版最高風險功能，因為自由文字可能出現不適當內容，也可能暴露暱稱與戰隊。

### 解法

採四段式流程：

1. 學員提交 1 則答案。
2. 系統依戰隊分流，同隊只看同隊投稿池。
3. 隊內初選 60 秒，每隊取前 3 名候選。
4. 講師每隊選 1 則代表作品，再匿名為作品 A 至 E，開放全體投票 60 秒。

限制：

1. 前端隱藏戰隊與暱稱。
2. 後端限制不可投自己隊。
3. 講師端必須先審核代表作品後，才可開放全體投票。
4. 自由文字不得寫入公開 Firebase 路徑，除非已匿名且經講師確認。

### API 規劃

| action | 使用者 | 說明 |
|---|---|---|
| submitCreativeAnswer | 學員 | 提交創作答案 |
| getTeamCreativePool | 學員 | 讀取同隊投稿池 |
| voteTeamCreative | 學員 | 隊內初選投票 |
| selectCreativeFinalists | 講師 | 講師選代表作品 |
| getCreativeFinalists | 學員 | 讀取匿名作品 A 至 E |
| voteCreativeFinal | 學員 | 全體投票 |
| getCreativeVoteResult | 講師 | 讀取票選結果 |

### 驗收標準

1. 每位學員只能提交 1 則答案。
2. 隊內初選只能投同隊投稿。
3. 全體投票不可投自己隊。
4. 全體投票頁不顯示戰隊、暱稱或玩家 ID。
5. 講師未審核前，作品不公開給全體。

## 第 3 版不做事項

1. 不升級 Firebase Blaze，除非使用者明確改變免費方案限制。
2. 不把抽獎或道具判定放在前端。
3. 不把正確答案、管理密碼、Token 或服務帳戶金鑰放入 Git。
4. 不在 Realtime Database 保存完整作答紀錄、完整投稿審核紀錄或管理操作密碼。
5. 不一次實作所有第 3 版功能；每個子版本需可獨立測試與還原。
